# RAG 量化检索：质量与速度对照实验方案

日期：2026-10-15。状态：方案，尚未执行本轮 SQ8 对照。范围只包含通用知识、外部案例和合成向量，不读取商家私有素材或改动业务索引。

## 1. 目标与已有证据

要回答：相同向量与查询下，SQ8 或扩大二值候选，能否在最近邻召回达到 95% 的前提下，比 float32 精确检索更快；在真实公开语料上是否损害语义召回？

已有完整 3600 万合成向量实验：float32 精确扫描的 8 查询批次耗时 114.64 秒；二值粗筛后精排 10000 个候选耗时 66.03 秒，但最近邻 Recall@5 只有 62.5%。这是批次耗时，不是单请求 P95；SQ8 尚未测试。既有结果仅作回归对照，不作为本轮新测试结果。

先定位损失：分别记录正确邻居是否进入候选集、进入候选后是否正确排进最终 Top5。浮点精排不能补回粗筛已经丢掉的正确邻居。

## 2. 实验组：三组必须使用相同原始数据

| 组 | 粗筛与最终输出 | 用途 |
| --- | --- | --- |
| A：float32 基线 | 原始归一化 float32 向量精确余弦检索，返回 Top5 | 速度基线及精确最近邻 gold |
| B：二值＋扩大候选 | 每维按零阈值编码 1 bit，Hamming 粗筛 TopL，再用原始 float32 精排 Top5 | 检查更多候选能否补回召回及其成本 |
| C：SQ8＋浮点精排 | 训练后每维 8 bit 标量量化，近似分数粗筛 TopL，再用原始 float32 精排 Top5 | 检查保留更多数值信息是否更划算 |

诊断组 B0/C0 只记录同一粗筛排序直接截断的 Top5，不重新搜索，用于解释重排收益；不能把重排前后改变候选预算算作重排收益。

B/C 在相同 L 下比较编码方案；每种方案另画 L 的质量—耗时曲线。最终选择允许两组使用不同 L，但该比较只说明整套方案的取舍，不能单独归因于量化精度。

首轮沿用分片流式精确粗筛框架，三组统一 NumPy 后端、线程上限和分片大小，不同时加入 HNSW/IVF。SQ8 需要的分块反量化、归一化和距离计算全部计时。以后若测试 Faiss/Milvus 的 SIMD 或图索引，另建实验；不能把换后端和量化混在一起称为纯量化收益。

## 3. SQ8 的实现约束

- 先归一化原始 float32；从语料向量中固定抽样训练每维量化范围，冻结训练样本 ID、参数和 hash。训练可使用未标注语料，不能使用测试问题、gold 或测试结果。
- 首轮只使用一种范围策略：训练样本逐维 min/max，256 个量化水平；范围相同的维度单独处理，越界值裁剪。记录各维范围、文档与查询的裁剪比例。
- 查询使用与文档相同的范围。不能直接 `astype(int8)`，这会丢失小数，而不是完成标量量化。
- 本轮近似分数明确定义为量化后重建向量的余弦相似度；需要的重建范数或额外存储单独记账。最终精排统一使用原始 float32 余弦。
- 二值零阈值策略保持既有实现，不同时加旋转、学习阈值或换 embedding。后续变换另做消融。
- 文档/查询量化耗时、训练耗时、索引构建耗时与在线检索耗时分开。在线必要的查询量化不能移出计时。

## 4. 两套语料，两种召回，不混报

### 4.1 通用知识与外部案例：语义有效性

使用已核验的公开 43 片段快照：30 个内置通用/业务公开参考片段、13 个外部文章与图片描述片段。从公开快照读取，不读取当前全部私有知识集合。固定正文、来源、ID、384D embedding 与查询向量。

沿用既有来源家族开发/测试划分，候选预算只在开发集选择。已经反复使用过的旧题作为回归题；已有新增措辞题也只作回归。正式确认应另准备至少 60 道新措辞可回答题、20 道缺事实题，运行前冻结 gold，明确单人标注或独立复核情况。

43 条的候选预算为 L=5/10/20/40；L 超出语料量时截断并去重配置。不能全部召回 43 条再精排，随后宣称量化粗筛无损。

报告两层结果：

1. 向量检索本身：对 float32 精确 Top5 的最近邻 Recall，以及对人工 gold 的语义 Recall。
2. 如果沿用现有标题/正文混合检索，三组全部使用相同词法结果、权重、融合规则及最终 Top5，再看最终语义 Recall。词法召回的补偿不能掩盖向量粗筛损失。

gold 中同来源文章/图片描述可替代与必须命中指定片段的题分开报告。缺事实题返回相似候选不直接算乱答；若没有生成答案，不填写答案正确率或乱答率。

这个小库用于发现实际语义退化，不用于证明千万级性能或真实原图理解。

### 4.2 合成向量库：规模、速度与近似损失

继续使用现有 3600 万条归一化 384D float32，不重新生成不同分布的数据。

| 阶段 | 向量数 | 冻结查询 | 目的 |
| --- | ---: | --- | --- |
| 初筛 | 100000 | 200：40 开发、160 测试 | 排除质量或性能明显不合格的配置 |
| 放大验证 | 1000000 | 同一规则生成并预先冻结 200 个新查询，40/160 划分 | 检查规模变化是否改变取舍 |
| 完整规模 | 36000000 | 新冻结 24 查询：8 开发、16 测试；旧 8 查询仅作回归 | 检查全库扫描、存储和粗筛损失；结论探索性 |

合成查询一半为加噪后的来源向量，一半为独立随机归一化向量；来源向量不直接作为无扰动自身查询。固定噪声、随机种子、查询 hash，两类结果单独列出。

每个规模独立计算全该规模的 float32 精确 Top5；候选不能拿子集 gold 评完整库。8/16 查询规模不能宣称稳健 P95 或线上 QPS。若需要完整规模单请求 P95，须另扩为至少 200 个独立请求并实际逐请求计时，不从共享批次耗时相除得到。

合成候选预算 L=1000/10000/20000/50000，统一截断至 N 并去除重复配置。先在开发集选定每种编码的一个 L，再跑测试。完整规模主计时只跑两个锁定的 B/C 配置与基线，不为每个参数重复做全库扫描。

## 5. 固定项与运行规则

同一份数据文件、查询向量、归一化方法、维度、Top5、距离定义、精排公式、机器、线程数和存储介质。记录源码/依赖版本、数据和参数 hash。所有派生索引与输出使用新的实验目录，原始库只读。

查询缓存在主实验中关闭；冻结向量输入表示本实验只测检索，不含文本 embedding 或生成。若要测文字请求全链路，三组另用相同 embedding 与缓存策略，额外报告；不能靠只给量化组加缓存证明量化提速。

100000/1000000 阶段逐查询、随机交替组顺序，每题至少 3 次。重复是稳定性测量，不算新增独立查询；独立进程运行块也随机排序。先预热，主表报暖态；首次访问/新进程单独报告，不把新进程当成 OS 冷缓存保证。

完整规模每种方法按相同批大小与固定顺序规则运行，明确共享批次扫描。若从同一次 Top50000 粗筛中截取不同 L，只能用于质量消融；独立端到端计时必须真实执行选定 L，不能沿用最大候选的扫描成本后声称小候选真实速度。

原向量读取、随机 I/O、候选合并、去重、原向量重排均计时。候选按分片归集读取的优化对 B/C 一致，不仅给一组使用。记录失败、超时和读文件错误，不能只统计成功请求。

阶段开始前计算磁盘/内存需求并固定资源上限；首次块试跑估算完整规模时间。资源超限就停止该阶段并留下状态，不把未运行或中断项填成成功。原语料不删除，派生索引的额外占用单独记录。

## 6. 核心指标

| 指标 | 定义与用途 |
| --- | --- |
| 候选 Recall@5 | 精确 Top5 中进入 TopL 候选的比例，定位粗筛损失 |
| 最终邻居 Recall@5 | 原向量重排 Top5 与精确 Top5 的交集比例 |
| 语义 Recall@5 | 命中人工必要证据的比例；多证据题另报是否找齐 |
| 完整证据率 | 至少一个完整 gold 证据组合全部命中的题比例 |
| 单查询 P50/P95 | 只用于实际逐请求测量的阶段，包含查询量化、粗筛、读取和精排 |
| 完整扫描批耗时 | 全库共享批次墙钟耗时，不称单请求延迟 |
| 阶段耗时 | 查询量化、粗筛、候选读取、精排分别计时 |
| 资源 | 进程峰值 RSS、原始向量、压缩向量、索引/ID/范数/参数和总磁盘占用 |
| 离线成本 | 训练、编码、索引构建时间；冷态和暖态分别列出 |

理论向量值大小：float32=55.296 GB；SQ8=13.824 GB；二值=1.728 GB（3600万×384维）。这些不包含索引、ID和范数；保留 float32 时，总系统占用不能宣称减少 4 倍或 32 倍。

原向量精排的最终邻居召回应与候选 Recall@5 一致，浮点并列/数值误差按预先固定规则处理。二者明显不同先查实现错误，不急于调参。全排序的并列距离统一按 ID 排序，粗筛分块保留规则也必须一致。

## 7. 验收与方案选择

开发集开始前锁定如下目标，不能看到测试结果后降低门槛：

1. 合成库最终邻居 Recall@5 ≥95%，噪声/随机两层也分别 ≥95%；低召回但快不算合格。
2. 公开语料语义召回相对 float32 下降不超过 2 个百分点，完整证据率也不明显退化。
3. 在上述质量门槛下，逐请求阶段检索 P95 至少下降 20%；完整规模另要求批耗时下降 20%，分别得出结论。
4. 无候选数越界、ID错配、原向量读取错误；保留全部失败记录。

选型规则：先剔除质量不达标方案，再从达标者中选择最快者；若速度相近，比较总 RSS、存储及构建成本。未出现达标的 B/C 时保留 A，报告“本批数据下量化没有取得合格取舍”。

按独立查询做配对 bootstrap，语义题按关联来源家族聚类，给出召回差值、P95比值及95%区间。重复请求先按题归组，不能当独立质量样本。点估计达标但区间不足以支持门槛时，标为探索性通过，不能保证生产召回达到95%。正式保证需增加独立查询并使相应区间也支持门槛。

3600万新测试只有16查询，定位为完整规模小试验；无法给出稳健总体召回保证。旧8查询不可用于参数选择后再次证明泛化。合成邻居 recall 不替代真实语义 recall，公开43片段也不能代表真实大语义库。
