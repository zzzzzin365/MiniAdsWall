# 回答前证据检查：已接入代码

复用项目现有模型客户端，没有引入 Jev。检查默认开启，服务重启后读取配置。

## 接入位置

| 入口 | 当前行为 |
| --- | --- |
| `/chat` | 安全确认通过 → 广告工具 → 查询改写、并行召回、去重、重排取 Top-3 → 逐段过滤 → 检查完整回答是否有证据 → 生成或说明缺失 |
| `/search` | 保留改写、并行召回和重排；按稳定片段 ID 去重后检查，返回过滤后的片段和 `evidence` |
| 托管任务 | 仅在原有 `HOSTING_RAG_ENABLED=true` 时启用相同增强检索与证据检查；检查记录写入持久化运行 trace |

安全门的 clarify/reject/confirm 分支不会触发检索或证据模型。纯寒暄跳过检索。已有经过人工整理的独立 FAQ 快速回答保持独立，不声称通过了本检查。托管 RAG 开关默认仍为 false。

## 回答行为

每个候选只检查最多 600 字，回答模型也只看到这些已检查的文字。代码校验每段分数、片段 ID、引用范围与判断状态，剔除阈值以下的片段；fallback 错误说明不能成为证据。

第二次检查只看保留片段和本轮业务工具结果，不将历史助手回答当作事实。允许依据已有规则做计算；业务工具数据足够时，即使没有知识片段也能回答。创作要求可以用于写文案，不能证明销量、收益或项目规则。

- `sufficient`：进入回答模型，只注入保留片段。
- `insufficient`：跳过回答模型，直接列出具体缺失信息。例如缺少转化和成本数据时，不能报“加价 10% 的收益”。若已有出价模拟，直接展示工具算出的出价与排名分数，标明不是收益预测、没有修改广告。
- `unavailable`：检查超时、服务失败或输出校验失败，说明尚未核实并建议重试；不悄悄放行生成。检索服务失败和成功检索但没有结果分别记录。
- `disabled`：人为关闭检查；记录明确标为未检查。

`/chat` 新增 `knowledge_evidence`；证据不足或检查不可用时，`decision=clarify`，`decision_reason` 分别为 `rag_evidence_insufficient` / `rag_evidence_unavailable`。`/search` 检查不可用返回 503，而不是伪造成功的空结果。

## 配置与记录

```dotenv
RAG_EVIDENCE_ENABLED=true
RAG_EVIDENCE_THRESHOLD=0.7
RAG_EVIDENCE_TIMEOUT_SECONDS=8
```

`0.7` 是临时起点，模型打分不是校准概率。两次检查共用 8 秒总时限；有候选时最多增加两次模型调用，没有候选时增加一次。保留 `/chat` 原有 28 秒总上限，因此新增检查可能挤占生成时间，需在真实模型上测量。

2026-10-12：聊天和托管任务复用 `search_with_rewrite`，不需要前端调用 `/search`。保留原问题，最多增加 3 个改写查询，每路召回至少 5 个候选，按片段 ID 去重，再重排选 3 个。改写、并行召回、重排各限 3 秒，聊天检索总等待上限 9.5 秒；改写失败回到原问题，重排超时保留候选原顺序，全部召回失败走不可用提示。聊天在增强检索内部不做证据检查，统一与业务数据结合后检查一次，避免重复检查或提前过滤。最多新增两次模型调用用于改写和重排，受原 28 秒聊天总上限约束。运行中的服务需要重启才加载新代码。

接入回归使用模拟检索和模型输出，覆盖运营/素材请求、去重、部分召回失败、改写/重排超时、全部召回失败、证据过滤和托管失去租约；未测真实模型召回收益或线上延迟。

把 `RAG_EVIDENCE_ENABLED=false` 可关闭新增模型检查，接口会返回 disabled。该开关不会恢复以前允许补写业务事实的提示。

JSON 日志 `rag_evidence`、聊天记忆元数据和托管 trace 记录：检查 ID、版本、候选/保留/拒绝片段 ID、分数、缺失信息、错误状态、阈值、检查耗时、模型调用数和提供方返回的 Token/成本。检查日志只保存问题哈希，不复制问题、候选正文或原始服务异常。成本没有返回时为 null；以上调用成本只覆盖新增检查，完整 A/B 脚本另统计生成和评审成本。聊天 `latency_ms` 现覆盖整个处理流程。

Chroma 查询移到后台线程，使检索等待可以按截止时间取消；线程内已经开始的只读查询不能被强制停止。

## 验证边界

离线回归覆盖真实 HTTP 处理函数、片段过滤、业务数据独立回答、收益缺失时保留真实模拟、错误输出与超时、配置回滚、安全确认，以及本地 SQLite Worker trace 持久化。结果见 `docs/evidence/rag-evidence-runtime-validation.json`。

这验证的是接线和控制行为，模型判断与 Chroma 返回在测试中被替换。未完成新版本的真实模型 A/B，也没有生产部署、真实流量错误率或延迟数据。旧试验只有 7 对完整样本，不能据此宣称错误率已下降；具体复查见 `docs/evidence/rag-evidence-ab-pilot-v1-review.json`。

固定问题评测现在支持 `--gate-version runtime-v2`，旧 `pilot-v1` 保留原始检查与提示供复查。运行新版本时保存新的输出文件，不覆盖历史结果；进一步评测后再决定阈值。
