# MiniAdsWall 多模态 RAG 优化对照实验方案

日期：2026-10-14。状态：通用知识/外部案例/合成向量实验已完成；用户进一步授权使用商家实际图片，现加入原图理解与最终生成的全链路实验（见第 15 节）。下文验收数字均为目标，实测数字以独立报告为准。

## 1. 范围与要回答的问题

主实验针对商家创意工作台：历史素材检索、图片/视频证据理解、创意草稿生成。悬浮 Agent、`/chat`、`/search` 使用不同调用链，不能混入同一组统计；以后可按入口另建对照。

要验证四个假设：

1. 原问题和结合当前附件的检索描述分别查询，能否找回原问题遗漏的相关素材？
2. 找到素材后按问题重读原图/视频帧，能否纠正历史描述遗漏的细节？
3. 判断证据缺口并有限补查，能否减少无依据回答，而不过度拒答？
4. 收益是否抵得上额外模型调用、耗时、输入 tokens 和索引存储？

创意是否更受欢迎、CTR/CVR/ROAS 是否提高，需要另做真实投放实验。本实验不把离线问答分数转换成商业收益。

## 2. 当前基线，必须按源码复现

| 环节 | 当前行为 |
| --- | --- |
| 语料授权 | Koa 从 MySQL 读取当前品牌、环境、最新素材版本及成功理解任务，当前附件优先，最多 100 个素材 |
| 素材理解 | Seed 读取图片或最多 8 个视频抽样帧；帧时间上限 60 秒；不处理音频 |
| 索引 | `core/multimodal_rag.py` 将 subject、marketing_summary、帧 description 转成文字片段，存入 `studio_media_caption_cosine_v1` |
| 查询 | message + subject_description + idea，截断到 6000 字符；按授权 chunk ID 白名单查询 |
| 内部召回 | cosine，Top5，默认相似度下限 0.25；分数不是答案正确概率 |
| 外部资料 | `mcp/external_marketing.py` 独立查询，Top3、下限 0.25；外部作者观点不能充当当前商品事实 |
| 生成 | DeepSeek 接收文字观察、retrieved_media、reference_knowledge；不直接读取原文件 |
| 引用 | Python 拒绝未知 source_ids/reference_ids；Koa 再校验权限、素材版本与理解任务 |
| 无命中 | 可以继续生成文字草稿，不应声称找到素材依据；检索故障返回错误 |

依据：`api/studio.py`、`core/multimodal_rag.py`、`apps/mini-ad-wall/server/services/merchant/studio/knowledge.ts`、`worker.ts`。执行前重新记录源码与配置快照，不能把本方案中的默认值当成未来运行值。

有效引用 ID 只证明引用来自候选集合，不证明候选支持答案；两者单独评测。

## 3. 逐项对照，不一次更换整个系统

所有组使用同一份原始素材、历史理解结果、问题、业务简报、权限快照、外部资料目录、DeepSeek 版本与输出 schema。每组每题都重新生成答案；不能重放同一答案来证明生成质量改善。

| 组 | 行为 | 对照与归因 |
| --- | --- | --- |
| A0 无历史 RAG | 保留当前附件理解和完整业务简报，只去掉历史 retrieved_media、外部 reference_knowledge；system 明确未启用这两项检索 | 诊断没有历史检索时的表现 |
| A1 当前基线 | 按第 2 节原样运行 | A1−A0：历史内外部 RAG 的整体价值，不能分别归因到内部或外部 |
| A2 多路文字查询 | A1 原查询 + Seed 基于问题和当前附件产生的检索描述；每路内部 Top5，使用 RRF 合并，保留内部最多 5 片段 | A2−A1：新增查询路线的收益与成本 |
| A3 按问题重读 | 原样复用 A2 的候选排序；Seed 重读已命中的授权原图或帧，将可见事实与不确定信息交给 DeepSeek | A3−A2：重读收益；候选集合不得变化 |
| G 只判断充足性 | A3 + 判断任务所需事实是否齐备；不足时说明缺项，不执行补查 | G−A3：证据判断带来的错误回答/误拒答变化 |
| A4 有限补查 | 与 G 相同的判断器；缺证据时追加一次针对缺项的检索/取帧，再判断并生成 | A4−G：补查本身的收益；不能全部归因于判断器 |

A0 是诊断组，A1 是主要产品基线。若需拆分内外部价值，再加“仅内部”和“仅外部”两组；首轮不增加。

A2 借鉴 TrioRAG 的多信号查询与排名融合，但只有文字路线，不称为完整 TrioRAG。原查询保留；新描述只用于查找，不能作为商品事实。RRF 的 k=60 固定，不能把余弦分数直接与 RRF 分数比较。0.25 只作用于各路原始余弦候选；合并后不再套用该阈值。同一 chunk 去重，每个素材最多 2 个片段；此去重/上限规则也应用于配套的 A1-normalized 对照。主表仍保留原样 A1，另报 A2−A1-normalized，避免把去重收益算作查询收益。

首轮只改变内部召回；A1 至 A4 的外部查询和结果逐题冻结。外部排序优化另开实验。A0 去除外部检索，因此 A1−A0 只支持整体结论。

A3 每题最多重读 3 个素材、总计最多 8 张图片/视频帧，优先覆盖相关素材，避免同一视频占满预算。各组当前附件理解固定；重读费用单独记录。Seed 的固定系统规则、版本和结构化 schema 不变，只有重读提示带本轮问题。DeepSeek 的固定规则和结果 schema 不变，新增观察通过数据字段注入。

G/A4 的判断器返回 `sufficient / insufficient / unavailable`、证据 ID、缺失事实、可选后续查询。语料不能证明商品功效/销量的题，不允许靠生成新查询把资料中的宣称变成 confirmed_facts。创意开放题只判断 factual 部分，不能因为缺“唯一正确创意”而拒绝构思。

A4 最多初查 + 1 次补查，最终仍最多 5 个内部片段、3 个外部片段；压缩、去重、替换后计入最终上限。视觉输入累计仍不超过 8 张。判断器最多 2 次调用。达到上限而缺证据，保留缺项，不把“循环结束”解释为证据充分。

额外取帧是待实现能力，限定原素材前 60 秒，不读取其他视频；记录新帧的真实 time_ms、文件 hash 和新证据 ID。现有最多 8 帧/次调用的协议需要实验适配器处理。初始帧与补帧分开记录，不能覆盖冻结的历史理解结果。未实现时 A4 仅测试文本补查，并把帧间遗漏题列为不支持；不得伪装已经补读视频。

总业务耗时预算先设 60 秒，作为待校准实验目标；实际 API 超时保持独立记录。补查剩余预算不足时停止。追加工作导致的超时属于该组失败，不能剔除。

## 4. 测试集：120 题，先标注，再运行

目标素材：6 个品牌，40 张真实或明确标记为合成的海报/商品图、20 条不超过 60 秒的视频，至少 20 个独立素材家族。准备相似但不相关的干扰素材；同一商品换版、裁剪、同视频帧属于一个家族。语料不足时缩为试验样本并披露规模，不拿重复改写题凑满。

按素材家族划分开发题与测试题，禁止同一家族出现在两份题集；跨素材题涉及的家族必须整体归入同一侧。两侧题都检索同一冻结语料，开发题只用于调参，测试题不参与调参。外部目录全组固定，标注其 preview/full coverage。

| 分层 | 例题/任务 | 开发 | 锁定测试 |
| --- | --- | ---: | ---: |
| 文字语义与创意参考 | 找到强调便携的历史广告；依据已确认商品事实写两条文案 | 6 | 24 |
| 必须看图的细节 | 价格位于画面哪个区域？哪张图采用左右对比？ | 6 | 24 |
| 视频时间与顺序 | 哪个抽样时间点出现产品？指定时间段先后展示了什么？ | 6 | 24 |
| 多素材组合 | 比较两份素材的 CTA；结合构图与已确认卖点生成草稿 | 6 | 24 |
| 合计 | 每层开发 5 可回答 + 1 不可回答；测试 19 可回答 + 5 不可回答 | 24 | 96 |

测试共 76 道可回答题、20 道不可回答题。不可回答原因覆盖：语料缺失、音频需求、图片模糊、未确认功效、证据冲突。跨品牌与旧版本排除另设确定性专项用例，不依赖这 20 题的小样本估计安全性。

标注者直接看原始图片/视频和 confirmed_facts，不只看 Seed 描述。每题记录：

- `case_id / family_ids / split / stratum / brand_id / environment`。
- 用户问题、当前附件 ID、完整简报、可以回答与不能回答的部分。
- 最小必要事实及可接受答案变体；创意题记录事实约束与构图要求，不指定唯一文案。
- gold 证据集合：asset_id、revision、analysis_job_id、chunk_id、帧 time_ms 或实际时间区间；允许多个等价证据集合。
- 每个证据的必要性：删除它后是否仍能回答；对图文组合题注明图和文字各支持什么。
- `raw_answerable`：原始授权素材能否回答；`caption_answerable`：冻结描述是否已覆盖；`initial_frame_answerable`：初始抽样是否覆盖。这三项不互相替代。
- 评审者与争议处理记录。金标准仅用于评分，严禁输入查询扩展、充足性判断或生成提示。

“视频第几秒出现”不能用抽样帧证明首次出现的精确秒数。用人工回看标注事件区间，或者把题目明确限定为抽样时间点；精确时间题的容差按标注的区间设定并锁定。抽样未覆盖时应说未知，禁止用相邻帧时间硬猜。

主实验比较共享输入条件：A0 也获得当前附件观察和商家文字。靠单个当前附件即可回答的题单独统计，避免稀释历史检索的价值。

## 5. 两条实验轨道

### 5.1 机制对照：定位改进来自哪里

冻结历史描述和文档向量、原查询向量；A2 新查询及其向量生成一次、记录 hash，之后逐组复用。A3 的 Seed 重读观察逐题逐证据缓存，G/A4 的共同初始部分复用，以减少模型随机性。

只允许复用比较双方相同的中间步骤。A3 不得复用 A2 最终答案；A4 新补查材料重新读；不同证据输入的判断器不能重放同一判断。固定随机种子、温度和解码配置；提供方不保证确定性时明确注明。

这条轨道用于解释机制，缓存命中耗时不能作为真实在线耗时。重放的模型步骤按原始 receipt 记录理论调用量与 tokens，不把实际重放零费用写成线上免费。

### 5.2 在线配对：衡量用户实际体验

先完成 A0/A1/A2/A3，只有前期有效才运行 G/A4。每题打乱组顺序，以小区组交替运行，避免 API 时间段和热缓存偏差；并发先固定为 1。共同历史索引处于暖态，不复用不同组新增的付费观察/判断缓存。当前附件理解可以共享，作为共同一次性成本。

记录冷启动/首次建索引开销，单独报告；暖态报告按题分组的端到端 P50/P95。此阶段不测线上并发容量。

从测试集中预先抽定 12 道题，各组额外运行 2 次，报告随机输出一致性；主比较仍用预先指定的第一次完整运行，不能挑最好答案。

## 6. 指标和评分口径

| 指标 | 计算与分母 |
| --- | --- |
| 素材 Recall@5 | 可回答题中，Top5 片段对应素材覆盖 gold 素材的比例；同时列 Hit@5，即至少命中一个 gold 素材的题占比 |
| 完整证据召回率 | 可回答题中，最终候选覆盖至少一个完整的 gold 证据组合的题占比；仅命中其中一张图不算完整 |
| 原始与描述覆盖差距 | 按 raw/caption/initial-frame answerable 分层，统计失败发生在检索前、召回、理解还是生成 |
| 有依据正确率（主指标） | 可回答题中，必要事实正确、无无依据事实且引用确实支持答案的题占比；生成失败计失败 |
| 视觉/时间题有依据正确率 | 上述主指标在视觉、视频两层的 38 道可回答测试题上的结果，样本较小，单独给区间 |
| 引用支持率 | 实际输出的“事实—引用”配对中，原始证据支持该事实的比例；无引用时为 N/A，另报可回答题引用覆盖率 |
| ID 合法率 | 返回引用属于该轮授权候选且版本有效的比例；与引用支持率分别列出 |
| 不可回答题乱答率 | 20 道不可回答题中，输出了缺依据关键事实的题占比 |
| 误拒答率 | 76 道可回答题中，明确拒答或未提供应答必要事实的题占比；接口失败另列，不算成功拒答 |
| 约束遵循率 | 创意题满足 confirmed_facts、未核验宣称不进入可发布文案等要求的比例；创意偏好评分单列 |
| 补查效果 | G 不足题中 A4 成功纠正的数量、A4 新引入错误数量、补查后仍不足数量、触顶数量 |
| 延迟/成本 | 各阶段耗时、P50/P95、调用数、tokens、图片/帧数、真实计费金额、失败请求支出 |

正确率分母固定为全部指定题，不能只算成功返回的请求；另提供“成功返回条件下”的次级结果。judge 失败列为未评分，给出覆盖率，不改判正确或拒答。

答案匿名、组名隐藏、顺序随机。两名人工评审独立审阅事实题的答案与原始证据，争议协商；报告一致率。模型 judge 可辅助标记，不替代人看图。创意题用事实约束评分加盲评偏好，不能用文案与参考答案的字面一致率评好坏。

图像/帧删除对照：从视觉组合测试题预选 12 题，移除必要图像，同时移除其文字描述和派生索引证据；保留其他材料，检查系统是否正确报告缺失。若保留描述，则是另一种“原图缺失但文字证据仍在”的实验，不能宣称证明了视觉必要性。

## 8. 专项正确性检查

不靠模型评分，复用并扩充 `tests/test_multimodal_rag.py`、`tests/test_external_marketing.py`、服务端 `multimodal-rag.test.cjs`。

覆盖跨品牌、跨环境、旧素材版本、撤权、失败理解任务、重复入库、未知引用、帧时间错配、资料夹带指令、未确认功效、Chroma 故障、Seed 超时、判断器返回非法结构、补查次数触顶。A2 的各查询、A3 的原图读取、A4 的新帧与新证据都必须走同一授权边界，不能只有首轮检索鉴权。

任何其他品牌/旧版本证据进入模型输入或原图读取，专项检查不通过。引用合法也不能豁免事实支持检查。

## 9. 预注册通过标准与统计

以下是工程目标，开发集后可调整一次并写入 manifest；看过测试答案后不得调整：

- A2 对 A1-normalized：完整证据召回率目标提高至少 5 个百分点；总体有依据正确率下降不超过 2 个百分点。
- A3 对 A2：视觉/时间可回答题有依据正确率目标提高至少 10 个百分点；不可回答题乱答率不增加。
- A4 对 G：可回答题误拒答率目标下降至少 5 个百分点；乱答率不增加；未达预算立即停止补查。
- 最终候选 R 对原样 A1：采用第 13 节的质量与速度联合目标。A2/A3/G/A4 即使单项有效，也不能代替完整 R 组对照证明同时改善。
- 所有组 ID/版本/权限专项检查必须通过；实际出现一次泄漏或读取越权就不能作为可上线候选。

配对报告差值、改善/恶化/不变题数。采用按素材家族聚类的配对 bootstrap（固定种子、10000 次）；跨素材题相关家族按连通分组，不能把相关题当独立样本。报告有效聚类数，数目过少时不宣称可靠显著性。主比较为第 13 节 R−A1 的联合指标；A3−A2 的视觉/时间有依据正确率改为机制解释的次级比较。

38 道视觉/时间可回答题、20 道不可回答题只能提供试验级结论。达到点估计目标但差值区间跨 0，标记“观察到提升，证据不足”；不能包装成确定提升。按试验观察到的配对改善/恶化率规划更大验证集，而不是凭空保证 120 题能检出目标收益。

## 10. 后续独立实验

| --- | --- | --- |
| 视觉索引（pplx/ColPali） | 固定原始素材、题目、原始证据 reader、生成器与最终证据预算；分别重建文本/视觉索引；若编码器也变，结论只属于整套表示方案 | 报告 Recall、答案质量、离线建库成本、索引字节数与 GPU/内存需求；不是直接替换当前 Chroma 查询 |

## 12. 如何证明速度、召回与取舍

### 12.1 速度单独对照：先找不牺牲质量的改动

多路查询、重读与补查通常增加工作量，第 3 节不能预设这些改动更快。速度实验先测试相同检索任务的执行优化，以下均待实现：

| 组 | 唯一变化 | 必须保持 |
| --- | --- | --- |
| S0 | 当前内部检索、外部检索串行执行 | 原查询、向量、过滤白名单、TopK、阈值、返回格式 |
| S1 | 同样两项独立检索并行执行 | 与 S0 逐题候选集合和各自排名一致；错误仍明确返回 |
| S2 | S1 + 查询 embedding 缓存 | 不缓存最终答案；仍实时计算授权白名单并执行检索 |

S1−S0 归因于并行；S2−S1 归因于 embedding 缓存。只缓存 embedding 的身份键包含 principal/品牌/环境、完整检索文本 hash、embedding 版本、归一化/dtype 配置。更新模型时失效。素材更新、撤权后每次仍走原授权与版本过滤；缓存不能代替 MySQL 判断。检索结果缓存不在此组范围，避免额外混入语料失效机制。

测量分两层：

1. 索引检索层：输入冻结查询向量，排除 embedding、重读和生成，测索引查找、过滤与合并；并行组分别报告每个分支与墙钟总耗时。
2. 用户检索层：从收到问题开始，包含授权、查询 embedding、必要查询扩展、检索及融合，结束于最终证据准备完成；生成完成的耗时另报，不能称为纯检索速度。

真实语料：使用锁定的 96 测试题测检索，每题至少 5 次，按题随机交替执行 S0/S1/S2；不是增加独立质量样本。并发固定 1，随后独立用并发 8、32 各运行至少 1000 请求，输入序列、到达策略和队列上限全组一致。报告请求总数、独立查询数、完成率、错误率、P50/P95、QPS 和资源使用；排队时间不能剔除。机器、线程数、进程数、网络路径、索引 hash、存储介质一致，记录进程外资源干扰。

缓存冷启动、首次建库、暖索引各自报告。S2 分别测全 miss、hit，并用受控的 0/25/50/75% hit 工作负载测总体 P95；这些是模拟比例，线上实际 hit 比例只能从真实请求日志获得。为缓存组重复同一个问题获得的速度不能外推到全新问题。可对速度差值按题做配对 bootstrap；报点估计和区间。缓存 miss/并行调度导致的回退也计入。

速度提升定义为 `(P95_S0 - P95_优化组) / P95_S0`。预注册目标示例：P95 至少下降 20%，对应质量指标不下降且候选一致性检查通过。若输入候选已不同，则退出“纯执行优化”结论，重新作为质量—速度联合方案评价。只有真实小语料结果时，结论限定该规模，不宣称千万级检索更快。

合成大库：已有 3600 万向量脚本是磁盘分片精确扫描，仅 4 个自身查询合批，不能据此给单查询 P95、QPS 或语义召回。后续若比较精确扫描与 ANN，需要复制相同向量到隔离索引并记录建库资源；先做 10 万、100 万规模，确认资源预算后再放大。

容量实验预选至少 200 个不只是查找自身的查询，包括扰动查询和独立随机查询；精确 Top5 作为向量邻居金标准。报告 ANN 邻居 Recall@5 = `|ANN Top5 ∩ exact Top5| / 5`（稳定规则处理并列距离），以及单查询延迟、吞吐、内存、磁盘与建库时间。该指标证明近似搜索是否漏掉最近邻，不证明广告语义召回提高。合批耗时和逐请求延迟分开记，不能简单除以批大小当单请求延迟。

### 12.2 召回单独对照：有人工 gold，才能证明找得更对

真实测试题用人工 gold 集合，第 6 节已有素材 Recall、Hit 和完整证据召回。A1-normalized 与 A2 使用同一 Top5 最终预算；不能把基线 Top5 与优化 Top20 的数字直接作为同预算提升。对 raw answerable、caption answerable、初始帧覆盖分层报告，解释召回失败是向量排序还是描述根本缺事实。

素材召回率计算 `检索到的 gold 素材数 / 全部 gold 素材数`，按题宏平均；跨素材题同时报告全部必要素材是否找齐。新增视觉编码器时固定原始素材和最终预算，但必须各自重算向量；不能假装向量空间也相同。最终答案质量另测，召回提高但引入噪声导致回答变差也算实际结果。

主报告中并列两种 Recall，明确命名：真实语料的“人工标注语义 Recall”与合成库的“精确最近邻 Recall”。不把后者拿来证明前者。开发集可做筛选，测试集只做锁定方案最终验证。

### 12.3 质量—速度曲线与按需升级

开发集扫描每路候选数 5/10/20，最终输入预算在同一轮比较中固定为内部 5、外部 3；分别记录召回、最终有依据正确率、检索 P95、端到端 P95 和模型成本。最终输入 TopK=3/5/10 的扫描另画一条曲线，不能与每路候选数混为同一变量。视觉重读数 0/1/3，补查次数 0/1 分开实验；所有模型输入和各项花费计入。

对可配置的 ANN 搜索宽度另做邻居 Recall—延迟曲线，参数名和合法范围先按实际安装的索引版本确认。变化搜索宽度时向量、索引构建配置、TopK 与查询不变。画散点图，X 为 P95，Y 为有依据正确率或语义召回，气泡大小为单题成本；去除那些同时更慢、更贵且质量不高的方案。

选择规则预注册：在质量达到最低门槛、乱答率不恶化、权限检查通过的配置中，选择 P95 最低者；若最低质量门槛无法达到，报告无可选配置，不强行宣称优化成功。延迟优先方案允许的质量损失、质量优先方案允许的延迟/成本涨幅都需在看测试集之前锁定。

待验证的产品策略：先执行便宜的原查询；涉及视觉细节或已知证据缺项时增加结合附件的描述查询；候选已经找到但缺本轮事实时才重读；仍缺明确事实才补查一次。不能把单个余弦分数当“证据够用”的概率。路由本身若调用模型，其费用、耗时也计入。

把这种路由作为独立 R 组，按第 13 节同时对照原样 A1 和“全部问题固定跑完整流程”的 H。报告升级触发率、漏升级/多升级数、质量、P95 和成本；按图/视频难题分层，避免多数简单题掩盖难题退化。每次选择可由 task 类型、证据缺项与预算轨迹解释，不能拿人工 gold 控制是否升级。

最终面试证据必须能指向：固定输入 manifest、逐请求计时、人工 gold、逐题改善/恶化、质量—延迟曲线、选择理由和反例。文档中的 20% 或其他提升阈值是目标，所有实测数字在实验前保持空值。

## 13. 围绕“质量与速度一起改善”收敛主实验

本节取代只允许最终方案变慢的旧目标。召回是定位问题的中间指标；联合质量主指标使用有依据正确率，防止把“找到更多但回答更差”算作优化成功。

### 13.1 主测试四组，机制组留作解释

| 组 | 执行方案 | 要回答的问题 |
| --- | --- | --- |
| A1 | 原样当前基线，保持现有截断、串行与生成规则 | 优化前产品表现 |
| F | A1 + 在开发集选定并验证候选一致性的 S1/S2 执行优化 | 单纯执行优化能否提速而不损质量 |
| H | F + 每题固定执行多路查询、重读、证据判断与有限补查（A4） | 固定高质量流程的收益和速度代价 |
| R | 与 H 相同的执行优化、模型与预算上限，但按题决定是否走额外步骤 | 完整优化能否同时改善质量与速度 |

主要结论来自 R−A1。F−A1、H−F、R−H 解释执行提速、额外证据和路由各自的作用；R 与 H 的模型、证据预算和共同规则一致，防止把不同模型收益算作路由收益。若是新增语料/视觉模型，须另跑对应实验，不能改主实验的冻结输入。

机制对照不是要求全部配置都跑满付费测试。开发集先验证 A2/A3/G 的局部作用；主测试只跑预先锁定四组，减少费用和从大量配置里挑最佳的偏差。

### 13.2 两个主指标一起判定，其他指标作为约束

| 项目 | 锁定前的工程目标 |
| --- | --- |
| 质量主指标 | R 的总体有依据正确率比 A1 提高至少 5 个百分点 |
| 速度主指标 | R 从收到问题到证据就绪的暖态 P95 比 A1 降低至少 20% |
| 用户全链路 | 到最终响应完成的 P95 不高于 A1；若只证据准备更快，只宣称这一阶段改善 |
| 难题保护 | 视觉/时间层有依据正确率分别不下降；单独报告每层延迟，不隐藏慢题 |
| 错误与成本 | 乱答率、接口失败率不增加；平均模型成本不超过 A1 的 1.5 倍，绝对单题预算在开发集后锁定 |
| 安全与版本 | 权限、版本与合法引用专项全部通过 |

证据就绪计时必须包括授权、队列等待、embedding、查询扩展、检索、原图/新帧读取、Seed 重读、全部充足性判断和补查，不止向量索引查询。A1 结束点为候选就绪，R/H 为其最终证据就绪；共同起点相同。纯索引耗时只做诊断图。不能先把重读搬到另一个计时阶段，再声称检索提速。

质量差值及 P95 比值分别报告按素材家族聚类的 95% bootstrap 区间。只有质量差值区间下界 > 0 且 P95 比值区间上界 < 1，才能支持“两项存在改善”；目标幅度用点估计核对，区间不能支持的最低改善幅度不做保证。联合目标要求两项都通过，不能二选一后叫双提升。96 题若不足以收窄区间，结果是试验性而非已证明；依据开发试验中的配对变化与延迟方差另规划独立确认集。

另记录正确率不变且提速、正确率提高但变慢、同时改善、都未改善四类结果；有价值的取舍也如实报告，不强行把所有结果写成成功。

### 13.3 把容易题和困难题的路由写成可检查规则

在原有四个任务层之外增加难度标签：现有描述足够、须看原图、须读新视频片段、须跨素材、原始授权资料不足。标签由人工预先标注用于分析，不能传给路由。

路由可使用用户任务类型、已有观察/limitations、实际候选、schema 所需字段、运行预算等可见信息。先用程序判断能够确定的分支，只有无法确定证据缺项时才调用模型判断；该调用计入全部费用和计时。不要每题先调用昂贵路由模型再把其耗时排除。每题 trace 写出触发原因、执行步骤、使用预算和停止原因。

审阅两类错误：该升级却没升级（省时但答错），不该升级却升级（答得一样但变慢）。与 H 配对，记录由省略哪个步骤造成的答案退化；未知 gold 的正常运行不能靠标注文件作选择。

业务题型比例没有线上日志时，以固定平衡测试集作主报告，并额外模拟视觉/困难题占比 20/40/60% 的工作负载；模拟比例明确标记。改变混合比例后重新生成请求序列并测延迟分位数，不能对各层 P95 简单加权。不能靠增加简单重复题制造总体 P95 降低。

### 13.4 控制调参过拟合与计时偏差

24 开发题不足以支撑大网格搜索。首轮预先限定最多 6 个候选策略，不做候选数×帧数×补查次数的全部组合；观察到依赖多参数强交互时先扩开发集。按质量下限、延迟和成本约束选 1 个 R，锁定后只在 96 测试题上验证，不从测试集反选 R。

F/H/R 都执行相同的缓存预热规则；如果缓存是处理的一部分，A1 保持原样，但必须交代带来的命中率差异。各组用独立缓存命名空间和相同 TTL，不让先跑的 H 为后跑的 R 准备额外付费结果。历史索引可以共同预热，模型新增观察不能跨在线组共享。冷态、无命中、不同并发单独测。

端到端实验模型生成配置和输出限制一致，记录输出 tokens 与 stop 状态；不通过减少必答内容或截断答案来获得速度收益。超时/错误不能从 P95 样本中悄悄移除：全请求完成时间和失败率一并报告；未完成请求保留截止时间与删失标记，明确分位数是否可估计，不能把截止时长当成功响应延迟。

最终报告主表只需四行 A1/F/H/R，列出有依据正确率、完整证据召回、证据就绪 P95、最终响应 P95、成本、错误率、升级比例；附同一硬件和输入的质量—延迟曲线、分层结果、区间和反例。所有实测单元格在执行前保持空值。

## 14. 用户限定后的实际执行范围

用户授权“只基于通用知识和外部案例、合成压测库跑实验”。因此不读取商家私有素材、商家 SQL 数据或私有素材索引。本轮读取已归档的内置通用知识与外部公开资料快照，并逐记录校验 ID、正文、source 是否属于允许的公开目录。

使用 43 个文字/公开图片描述片段：旧题家族划分与开发集选定权重保持冻结；另外先冻结 38 道新措辞问题，再评价已选定配置。新题与开发集共用来源，不称为独立来源盲测。原始归档图片未送入视觉模型，本轮不能证明原图理解、视频理解、生成正确性或工作台路由的质量收益。

本轮四个检索对照为纯向量、缓存纯向量、向量与标题/正文关键词混合、缓存混合。它们不是第 13 节的工作台 A1/F/H/R；单独报告 0/50/100% 受控查询向量缓存命中工作负载，所有组保持最终 Top5。缓存 precompute 成本独列，没有新增付费模型调用。

合成实验分成：复用并随机重测 10 万向量隔离 HNSW 索引的搜索宽度；核验正在执行并完成的 3600 万向量精确扫描与二进制粗筛/浮点精排。小库使用 200 个查询及逐查询计时；全库仅 8 个查询合批，不能给全库单请求 P95 或并发 QPS。

执行脚本为 `evaluation/run_public_rag_tradeoff.py` 与 `evaluation/verify_public_rag_queries.py`。报告目录为 `docs/validation/general-rag-ab/20261014-v2/`；完整指标、限制和下一步建议写入其中 `report.md`，不能把近邻召回或候选返回率当成答案正确率。

## 15. 基于真实商家图片的全链路补充实验

用户最新授权覆盖商家素材库图片，并指定必要时使用 Doubao-Seed-2.0-mini。这扩展了第 14 节当时的公开语料限制。本轮只读当前未归档素材与图片表，找到 4 张可读取的真实 JPG；不修改广告、素材记录、生产 Chroma 集合或生产模型配置。

固定使用 `doubao-seed-2-0-mini-260428` 理解原图，使用原有 `deepseek-v4-1-flash-260910` 生成最终答案。该 Mini 模型以真实图片请求验证可用。初始通用理解所有组共用，按当前 caption-vector 模式建立隔离索引。素材标题显式引用查找对所有组共同启用，不拿来源覆盖率冒充向量召回提升。

| 组 | 图片与最终生成流程 |
| --- | --- |
| A1 | 仅通用图片描述与素材文案检索，DeepSeek 回答；query embedding 不缓存 |
| F | A1 + 查询 embedding 缓存；各组缓存独立，冷查询首次均为 miss |
| H | F + 每题都让 Seed 按问题读取候选原图，再交 DeepSeek 回答 |
| R | F + 固定问题词规则按需读取原图；不靠图片猜售价、材质、销量或认证；重复问题可复用版本/原图 hash/模型/问题/schema/prompt 绑定的视觉证据 |

预先查看原图并冻结 4 道协议检查题、20 道正式题与接受字段。正式题是 4 简单主体、8 细节、4 跨图比较、4 信息缺失题，另固定 6 题做重复工作负载。标注由本助手完成，没有独立人工盲评，不能视为足量独立测试集。

所有组使用同一 DeepSeek、同一输出字段和事实边界。原图重读和最终生成均为真实付费 API 请求，每次提交前独占写 receipt；不确定提交不自动重试，预算最多 160 个请求。密钥、认证头和图像 base64 不写入实验日志。提供方没有返回金额时保持 null，不填 0。

评测分成预标注字段与必要引用覆盖、严格引用集合诊断、缺信息拒答、误拒答、失败率、视觉调用数、证据缓存命中、证据就绪和完整响应 P50/P95。整个在线计时包含原图读取、Seed 理解和 DeepSeek 生成；共同初始理解/建库成本另报。重复问题不复用最终答案。4 个相关素材与每题每组一次请求只能给小样本结果，不能证明生产 P95 或普遍显著性。
