# 记忆接入与经验复用：实施与验收记录

日期：2026-10-20。结论：本地功能实现、自动测试和真实请求验证已完成；已对本机 `operator` 与隔离验证身份启用。生产建议质量验收尚未通过，不能宣称整体质量优于原版或带来收入/成本收益。

## 当前能力

| 能力 | 实际行为 |
| --- | --- |
| 两条入口统一 | 页面托管 run、同步 `/chat` 最终使用同一个 Worker、终态、消息库和记忆服务。同步不执行第二套模型循环。 |
| 可信同步身份 | 先校验服务凭据；已有托管 token 时由托管 Auth 解析身份；仅服务调用方可断言主体。Koa 用认证 principal 覆盖浏览器 userId。旧会话别名按主体持久映射到托管 session。 |
| 同步幂等/超时 | 浏览器与 Koa 传递同一 Idempotency-Key；同步等待最多 20 秒，未结束返回 202 与 run_id，保留原请求/key；之后继续在后台执行。旧客户端重试必须保留原 payload/key，不能把 pending 当完成。 |
| 摘要与历史 | 旧 Redis 摘要合并重写、有界、完整源文先归档，WATCH 防止并发删除新消息；新摘要存 MySQL，按成功消息水位生成；生成时避免重复注入已覆盖消息。 |
| 跨会话读取 | 同主体/工作区读取有效偏好；最多扫描最近 50 条有效摘要做确定性词项检索，最多注入 3 条情景片段。没有迁移旧 Chroma 集合，未声称使用向量重排。 |
| 偏好生命周期 | 白名单与原话校验；明确长期声明进入后台任务；冲突保存候选，由人确认；版本 CAS、撤回、完整偏好版本快照（从本次升级后开始保留，旧版本缺失值不补造）。精确偏好查询直接读结构化数据，不依赖模型复述。 |
| 后台可靠写入 | 只有成功生成或显式记忆声明才在终态事务中入队；取消、旧 fence、失败不会学习；任务租约、退避、五次上限、死信列表和显式重放；格式/长度至多修复一次。 |
| 经验库 | 实现 `marketing/feedback` 拥有的通用操作流程真值库，支持待审核、审核、撤回、过期、版本冲突和适用条件过滤。审核权限为 `memory.review_procedure`，不由模型授予。 |
| 来源与恢复 | 持久化选中的 id/kind/version/source_ref；同一恢复任务只使用原选中且仍有效的版本，已变更/撤回项丢弃；快照不保存记忆正文。 |
| 删除联动 | 源消息软删除后停用混合摘要、关联偏好与候选，清除相关版本正文，取消相关未完成请求；旧回复/工具输出预览脱敏，旧 SSE 返回 410，相关对象下载拒绝。新生成不会继续读该会话删除前的历史。 |
| 成本与降级 | 记忆总预算 3,200，采用保守 UTF-8 字节上界估算；超时降级不关闭原 RAG 证据门，完整短消息与长文本对象分别校验，不把截断预览当完整来源。 |
| 页面管理 | 助手内“偏好与操作经验”：更正/撤回偏好、确认冲突、清除摘要、检查流程全文后审核/撤回、失败任务重试。已检查浏览器无错误，展开后输入框仍可见。 |

本次经验库只接受通用流程，不接收品牌效果记录或百分比收益结论。它不能冒充完整反馈 SDD 的“建议采纳→执行回执→效果快照”。效果级案例仍需原业务反馈模块提供可信报表、品牌权限、执行与观察证据。

删除是应用层软删除与派生读取阻断，不等于抹除数据库备份、历史审计或已发送给模型提供商的内容。共享对象的物理回收遵循原存储保留策略；不能直接删除可能被其他记录共用的内容寻址对象。

## 真实模型对照及限制

模型为实际配置的 `deepseek-v4-1-flash-260910`，同一份 100 题合成数据，检查结构化长期目标、审核流程标题和未知预算。A 无长期记忆，B 使用原文字记忆格式，C 使用新装配服务。

| 组 | 结构化约束通过 | 给出有依据的非空目标 | 返回适用流程 | 模型响应 P95 |
| --- | --- | --- | --- | --- |
| A | 100/100 | 9 | 0 | 3,127.99ms |
| B | 100/100 | 66 | 0 | 3,034.49ms |
| C | 99/100 | 65 | 8 | 3,788.82ms |

这些分数判断是否忠实于该组可见信息；A 不知道时返回 null 也算正确，所以不能把三组的 100/100 理解成能力等价。C 增加了适用流程，但漏用了 memory-eval-094 的长期目标，未证明整体质量不低于 B；P95 也未显示提速。

初轮脚本将空目标的评分误记为 TypeError，原始结果保存在 live-evaluation-initial.json。修正评分后，复用未变的成功 A/B 请求，只重跑异常 A 请求和全部新版 C；最终没有运行异常。上下文标记已区分“有效用户偏好”与“历史投放事实”，仍如实保留剩余漏用样例。

最初记录 usage 时把字典当属性读取，报告中的 token 数为空；脚本已修正未来采集，但没有补造旧 token 数，也没有为补统计重复全部付费请求。因此当前不作成本下降结论，且这些调用的比较不包含后台提取摊销。

人工建议质量的双人标注尚未完成，human-review-template.json 明确保留未标注状态。生产建议验收、真实商家收益、规模容量与长期效果均不属于已验证结论；只开放本机限定主体，保留读写/经验独立开关。
