## 业务一致性

- 通过真实 HTTP 写入曝光、唯一点击、签名关联支付、部分退款、费用和费用更正；最终曝光 1、点击 1、订单 1、退款订单 1、净收入 700 分、净费用 800 分。重复消费不新增归因/日报计数。
- 支付先到、之后补入事件时间更早的点击，未归因转为归因；再补更新的点击，可改到另一素材，旧分区订单/收入归零、新分区只计一次。当前关联只保留一个归因 revision，历史仍可查。
- 上海点击日与支付日分离：点击日在日报只增加点击，支付日在日报只增加支付/净收入；click_orders 留存两个时间，可按点击人群查询，避免误算同日 CVR。
- 同一组经济事实分别按支付→退款、退款→支付写入，每阶段独立消费。原始退款状态仍为 pending，最新校验为 valid 时 Worker 正确扣款；最终两订单各净收入 800 分，总额 1600 分，点击关联 2 个订单。显式重建前后当前指标精确一致。
- 40 天前的受信原始数据夹具自动标记待重建；显式重建后原支付日为 1000 分。新退款到达，原日报保持旧值并标记待重建；再次重建得 600 分、退款订单 1，清除标记并保留原日报 revision。
- 单元验证 E05：支付前 7 天边界可归因，多 1 毫秒/支付后点击、不同会话/商品/品牌/环境、隔离点击均排除；同时间按 click_id 稳定选取。无匹配和无会话均保存原因。

迟到点击、跨窗导入及跨素材移动使用测试专用的受信原始夹具和不可变 decision；不修改已接收事件，也不宣称消费者公开接口允许伪造会话或导入历史点击。真实公开入口的来源认证、签名与时间隔离沿用 CP02/03，均在本次全量回归中通过。

## 故障和权限

- 独立 Worker 在派生写入后、COMMIT 前直接退出：结果回滚，原任务仍 running；租约过期重领后正确提交。COMMIT 后退出：done 和派生结果保留，重启不重复计数。
- 计算后让租约过期，旧代次提交失败；快照计算后接入新数据，输入 epoch 不匹配而拒绝旧结果；两个进程竞争 26 项任务，第一批只领 25 项，另一进程发布后旧 generation 被拒绝，重放最终 26 点击，只有一个有效日报版本。
- 未知 kind、坏事件引用、输入行数超限进入可观察 failed；达到 5 次尝试不再领，超过 24 小时拒绝提交。每品牌 10000 非 done 积压后 HTTP 接入返回 503，原始事件数量不增加，证明原事务回滚。
- 按实际 grants 文件创建临时专用 Worker 账号，独立进程正常消费；尝试修改 ads_business_ads 被 MySQL 拒绝，旧广告值保持不变。只给输入时钟 epoch 列额外 UPDATE 权限满足行锁需求，不给 Worker 写原始事实或插入 outbox 的权限。
- 入口设 MARKETING_EVENTS_ENABLED=false 的独立 Worker 仍能处理已接收数据；环境由命令显式指定，未打开后续阶段功能。
