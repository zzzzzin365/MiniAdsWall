# 模型排队与固定规则问答缓存

## 已接入的调用路径

`create_model_client()` 返回受控客户端，识别、实体提取、Agent 回答、记忆摘要、用户画像、工具查询改写和评测 Judge 均在实际模型调用前申请名额。创意/策略生成和 FAQ Embedding 也共用同一调度入口。不会为整个聊天过程占住一个名额后再次申请，避免嵌套死锁。

默认 local 模式：单进程有界等待与并发控制。多实例运行时设置 `MODEL_GATE_MODE=redis`、`REDIS_URL`，所有共享供应商额度的实例使用相同 `MODEL_GATE_NAMESPACE` 和配置。不同 namespace 是独立额度，不要给每个实例设置不同值。Redis 模式故障时拒绝新模型调用，不切回进程内额度。

Redis 用 Lua 原子操作三个有序集合：执行中的租约、FIFO 排队顺序、等待截止时间。使用 Redis 服务端时间，避免实例时钟偏差。默认最多 4 个执行、32 个等待；排队最多 5 秒，执行最多 45 秒。取消时清理票据；进程崩溃后，等待票据和执行租约会过期，由下一次调度回收。执行租约比本地硬超时多 5 秒，正常请求无需续租。

等待者每 50ms 重新检查权威状态；未引入发布订阅。队列保存等待调用的票据，不保存业务任务，进程崩溃后的请求不会自动重放。该机制控制同时执行数量，不是每秒请求数或 Token 配额。调用取消不能证明供应商已经停止远端推理；长时间进程暂停、网络分区及 Redis 数据丢失仍可能影响远端实际并发，需要供应商侧限制配合，不能宣称严格全局 exactly-once。

同一 namespace 的调度配置不一致会拒绝调用。变更额度时应先停止接入并排空旧请求，再统一更新配置与 Redis 的 `gate:{namespace}:config`；不能通过临时切换 namespace 绕过仍在执行的额度。

## 固定规则问答语义缓存

默认关闭，启用需配置 `FAQ_CACHE_ENABLED=true`、`FAQ_EMBEDDING_URL`、`FAQ_EMBEDDING_API_KEY`、`FAQ_EMBEDDING_MODEL` 和 `REDIS_URL`。Embedding 接口采用 `model/input` 请求和 `data[0].embedding` 响应格式。

`config/cacheable_faq.json` 是人工维护的范围白名单，当前只包含广告排序规则及三个明确问法。只有完全匹配白名单问法（允许末尾问号等标点变化）、无历史会话标识、无确认标识的请求才进入缓存路径。附加指令、实时投放分析、创意生成、修改操作及多轮追问全部绕过。白名单限制范围，向量相似度决定已存答案是否可复用；并未开放任意自然语言问题的语义匹配。

请求先向量化，在同一问题类别内匹配 Redis 保存的问答向量，默认余弦相似度至少 0.95。缓存隔离用户、权限集合、目录内容、知识版本、Embedding 模型与地址、回答模型与地址、提示词版本。仅回答目录中给出的规则，不注入广告快照、用户画像、Skills 或对话历史。未命中时生成答案，成功后写入 Redis；TTL 默认 1 小时。每个类别最多保存白名单问法数量的记录。缓存或 Embedding 故障时跳过缓存，按同一固定知识生成；模型失败不缓存。命中和生成结果均写入当前会话，后续追问恢复正常上下文流程。

修改排序代码或其他被缓存规则时，必须同步更新目录中的知识文本；缓存不会自动理解源码变化。缓存成功的模型回答也可能有事实错误，需离线评估后再扩大白名单。缓存命中仍有 Embedding 调用成本；应对比回答模型节省、Embedding 开销、命中率和错误复用率，不能直接写节省百分比。

## 验证范围

`python -m unittest discover -s tests -q` 包含真实隔离 Redis 的并发容量、FIFO、队列满、等待超时、取消清理、孤儿租约回收、配置冲突测试，以及缓存命中、低相似度、权限/用户/版本隔离和故障降级测试。Redis 测试需要本机 `redis-server`，启动的是临时 Unix socket 实例，不连接业务 Redis。

向量与回答使用测试替身，未验证真实 Embedding 质量和实际降本。这里没有日均吞吐、高并发压测或生产可用性结论。
