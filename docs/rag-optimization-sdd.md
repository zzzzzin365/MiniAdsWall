# MiniAdsWall RAG 优化 SDD

- 日期：2026-10-24
- 版本：0.1
- 状态：首版代码与本地功能验证已落地，默认关闭；正式效果验收与灰度未完成。本文指标均为验收目标，不是现有成绩。
- 实施与差异：[实现与运行](rag-optimization-implementation.md)。
- 目标：减少关键词漏检、上下文缺失和无依据回答，并量化检索质量、延迟与成本的取舍。
- 范围：先优化广告运营文本知识库；素材视觉检索保留独立链路，不在本轮统一改造。

## 1. 当前实现与问题

| 位置 | 已有实现 | 本轮解决的问题 |
| --- | --- | --- |
| [knowledge_base.py](../mcp/knowledge_base.py) | Chroma 向量检索；按句号和换行分块；余弦分数；有限规模检索故障回退 | 只有向量召回；无重叠；长句可能超长；导入元数据不完整 |
| [tool_manager.py](../mcp/tool_manager.py) | 问题改写、多查询并行召回、片段去重、大模型重排序、超时降级 | 缺少关键词召回；重排截取每条前 600 字；排序输出校验不足 |
| [rag_evidence.py](../core/rag_evidence.py) | 检查片段支持程度、资料充分性和证据 ID；区分资料不足与服务故障 | 检查结果依赖模型；不能替代生成后引用校验与独立评测 |
| [main.py](../api/main.py) | 注册知识工具；检索 API 和回答前证据检查 | 改造须覆盖真实入口，不能只新增无人调用的检索函数 |
| [pipeline.py](../hosting/pipeline.py) | 托管助手结合业务工具数据、知识检索和证据检查生成回答 | 保持统计窗口、样本范围和业务事实来源约束 |

现有多查询属于“多种问法查同一向量库”，不是关键词与向量混合检索。大模型重排序已存在，本轮不是首次引入。现有素材链路见 [multimodal_rag.py](../core/multimodal_rag.py)，不能用文本链路实验推断视觉效果。

历史证据检查实验见 [实验结果](rag-evidence-ab-results.md)，其中固定检索快照、合成业务数据和小样本结论不能当作当前全链路效果。

## 2. 范围与约束

本轮包括：版本化文档与分块、关键词与向量混合召回、父段补全、可替换重排序、引用校验、冻结评测和灰度回滚。

本轮不包括：知识图谱、自动训练嵌入模型、全量复杂 PDF/OCR 平台、真实广告竞价执行，以及把历史容量实验扩展为线上性能结论。PDF 先支持能提取正文的文件；扫描件、复杂表格解析另立设计。

必须满足：

1. 业务数值来自本轮授权业务工具；知识文章不能证明某条广告的收益、原因或实时状态。
2. 搜索范围由服务端确定。现有单知识池不能因增加 scope 字段就宣称已完成多租户隔离；开放私有知识前必须接入服务端授权。
3. 所有检索分支使用同一授权范围、文档版本和索引版本；权限过滤先于候选截断，补读父段时再次校验。
4. 索引是可重建的派生数据；源文档和发布清单是版本依据。
5. 检索失败、成功但无结果、资料不足分别记录；禁止回退到编造事实。
6. 通过片段检查不等于答案正确；引用有效也不等于引用支持结论。

## 3. 目标调用链

```text
服务端授权范围 + 原问题 + 本轮业务工具数据
  → 保留原问题，按预算补充改写问题
  → 向量召回 + 关键词召回
  → 按 chunk_id 合并，按排名融合
  → 重排序
  → 有界补全同文档、同版本父段
  → 现有证据检查
  → 结构化生成答案与引用
  → 程序校验引用，渲染答案与来源
```

默认先保留现有大模型重排，以便单独测混合召回；专用重排模型作为独立实验。父段补全先于证据检查，模型最终使用的补全文本必须接受检查。

## 4. 文档、分块与索引版本

### 4.1 数据合约

建议在 Python 服务侧增加版本化源文档存储接口；首版以 SQLite 保存文本知识文档、片段与发布清单，向量继续使用 Chroma。该 SQLite 不替代 Koa 的业务数据库。原文附件采用受控文件路径或对象引用，禁止将任意客户端 URL 当作可信来源。

| 对象 | 必需字段 |
| --- | --- |
| 文档版本 | doc_id、revision、scope_id、title、source_url（可空）、content_hash、normalized_text、parser_version、状态 |
| 父段 | parent_id、doc_id、revision、section_path、start_offset、end_offset、text |
| 检索片段 | chunk_id、parent_id、doc_id、revision、text、start_offset、end_offset、content_hash、chunker_version |
| 索引清单 | generation_id、文档版本集合摘要、embedding_model/revision、tokenizer_version、chunker_version、构建状态、发布时间 |

offset 使用规范化正文的 Unicode 字符位置，左闭右开；不得与 PDF 原始字节或 token 位置混用。文档重命名不改变 doc_id；正文或来源元数据变化生成新 revision。chunk_id 由 doc_id、revision、分块版本、位置和内容摘要确定，不使用标题与正文前几十字作为唯一依据。

### 4.2 分块规则

- 先按标题和段落划父段，再按句子划检索片段；无标题时按相邻段落组织。
- 初始配置：片段目标 400 字符、硬上限 600 字符、重叠最多 80 字符；父段最多 1,600 字符。参数必须带版本，通过评测再调整。
- 单句超过硬上限时继续切分；重叠不得导致循环或空片段。保留标题路径与对应正文位置。
- 表格在解析支持时保留表头和行的关联；无法可靠解析的表格明确标记，不生成看似完整的规则文本。
- 字符限制只是分块策略，最终请求还须遵守实际模型 tokenizer 的 token 预算。

### 4.3 发布、删除与兼容

新版本在独立 generation 内同时构建关键词索引与向量索引，核对片段 ID、数量、模型版本和抽样检索后，原子切换活动清单。请求开始固定 generation，禁止两条分支读取不同版本。

删除或撤销权限先进入服务端拒绝集合；即使旧索引仍有片段，也不能返回或补读。索引回滚不能恢复已删除或已撤权的文档。旧 generation 至少保留到所有在途请求结束，之后清理。

现有文档离线导出并重新分块，不在启动时直接覆盖原集合；缺少来源 URL 的文档保留空值，不编造出处。迁移期间通过配置选择旧链路或新链路，保留旧集合用于回滚。

## 5. 混合召回

关键词分支采用 BM25；首版以固定版本的中文分词器和用户词典建立索引，明确保留 CTR、CPC、CPA、广告 ID、型号、金额与数字。英文统一大小写；中文别名显式登记，不任意改写精确标识符。

初始有界参数：

| 参数 | 默认值 | 上限 |
| --- | ---: | ---: |
| 查询数，含原问题 | 3 | 4 |
| 每查询、每分支候选 | 20 | 30 |
| 融合后送入重排 | 30 | 40 |
| 最终检索片段 | 8 | 10 |
| 补全父段 | 4 | 6 |

采用排名倒数融合：`score = Σ 1 / (60 + rank)`，rank 从 1 开始。每个查询与检索分支构成一份排名列表；先将该列表内部按 chunk_id 去重，再融合。原问题始终参与，禁止把向量距离和 BM25 原始分数直接相加或当正确概率。

第一阶段只用原问题的向量、BM25 两份列表验证混合召回收益；多查询与混合检索结合单独评测，防止把额外查询收益算成 BM25 收益。精确编号必须原样保留到关键词检索。

某分支失败允许返回另一分支结果，但标记 partial、failed_branches 和降级原因；没有可用分支时返回 unavailable。降级质量单独统计，不与完整链路混报。

## 6. 重排序、父段补全与证据检查

统一重排序接口输入原问题、片段 ID、完整片段正文和标题路径，返回唯一且属于输入集合的有序 ID。校验类型、重复、越界和数量；非法输出整次重排失败，回退融合排名，并标记实际 rerank_applied=false，不能只因调用过就记成功。

提供三个实验实现：融合排名不重排、当前大模型重排、版本固定的中文专用重排模型。专用模型具体选型以本地依赖、许可证、中文评测和硬件预算为准，本设计不预先宣布其更快或更准。不得静默截断正文；模型输入超限时缩减候选数并记录截断情况。

按重排结果选子段，然后补充对应父段；同一父段只计一次。超预算时优先保留命中子段及其邻近上下文，并记录实际片段范围。父段本身也以精确范围生成 evidence_id，不能引用未进入本轮上下文的整篇文档。

继续使用现有 EvidenceGate 检查这些证据和业务数据。达到模型 token 预算时先裁剪证据再检查，不得检查一份文本、生成时另换一份。首版证据正文预算 4,000 tokens；另为系统指令、业务上下文和输出预留空间，以模型总窗口为最终硬限制。

## 7. 答案与引用合约

内部生成结果采用结构化对象：status、answer_blocks、missing_information；每个事实块含 text 与 evidence_ids。证据只允许来自本轮通过检查的片段，业务事实引用 business，并关联本轮工具记录 ID。

程序校验：

- 引用 ID 必须存在、已授权、属于固定版本且通过本轮检查；URL 和标题从服务端证据清单渲染，不接受模型编造。
- 原文摘录必须是对应证据正文的连续子串；模型改写不能冒充直接引语。
- 已撤销来源、未知 ID、越权引用一律拒绝输出相关事实块。
- 格式或引用校验失败，首版返回明确的生成失败说明与可查看来源，不再进行无界模型修复。

引用校验只证明来源与摘录对应。回答是否歪曲规则、计算是否正确仍需质量评测；不将“引用校验通过率”当作“事实正确率”。

## 8. 入口、预算与观测

新建共享检索服务供 `api/main.py` 的检索/回答入口和 `hosting/pipeline.py` 调用，保持原工具名 knowledge_search 兼容。原字段保留，新增 generation_id、retrieval_mode、partial、failed_branches、rerank_applied、sources 和 timings；未知字段兼容性须由入口合约测试确认。

首版仅对文本知识链路启用；`api/studio.py` 的素材召回不隐式切换到新实现。缓存键包含授权范围摘要、generation、查询、检索/重排配置版本；禁止跨权限、跨版本复用。

配置按阶段独立控制：分块/索引版本、hybrid_enabled、parent_expand_enabled、reranker_mode、citation_validation_enabled。新索引先影子检索，不改变用户答案；不得使用一个总开关掩盖各阶段归因。

沿用入口的总请求预算，阶段超时取“配置上限与请求剩余时间”的较小值；检索、重排、证据检查不得各自耗尽整条请求预算。超时、取消和调用失败计入全部请求分母。每次记录实际模型请求数、输入/输出 token、供应商费用（未知保持 null）、缓存命中，以及改写、分支召回、融合、重排、补全、检查、生成、引用校验的耗时。

日志记录 request_id、配置摘要、文档/证据 ID 和失败原因；私有正文与敏感业务数据不默认写入普通日志。对部分失败与降级分别统计，避免只看成功请求的漂亮数据。

## 9. 评测设计与验收

### 9.1 冻结数据

建立至少 120 题：规则解释、精确术语/编号、长文跨段、业务数据结合、资料不足/冲突、来源删除/越权各至少 20 题。构造题与真实问题分开标识。每题保存来源版本、必要证据范围、参考答案、可回答性和允许的业务数据；跨段题允许多个必要证据，不强迫只认一个 gold chunk。

按文档家族拆为开发集 40 题、冻结测试集 80 题；测试集不用于调参数。分块改变后以 gold 文本范围映射新片段，禁止沿用失效的旧 chunk_id。标签经人工复核；模型评分只作辅助，争议项保留原始输出和人工结论。

### 9.2 单独归因

| 组别 | 变化 | 对照目的 |
| --- | --- | --- |
| A | 冻结当前完整链路 | 真实基线 |
| B | A 仅改分块与来源元数据 | 检查上下文保留 |
| C0/C1 | B 均只用原问题；C0 向量，C1 向量＋BM25 | 单独检查混合召回 |
| D | C1 增加与 B 一致的改写查询策略 | 检查多查询组合收益 |
| E | D 仅增加父段补全 | 检查跨段回答与成本 |
| F0/F1/F2 | E 上分别不重排、大模型重排、专用重排 | 检查重排取舍 |
| G | 所选配置增加结构化引用与校验 | 检查最终输出可靠性 |

除被测阶段外固定模型、语料、提示、Top-K 与预算。C0/C1 使用相同的现有重排；F 组才切换重排方式。所有组沿用相同证据检查配置；无法保持一致的实验单列。保存失败结果，按文档家族报告配对差异和区间，不能只挑成功样本。

### 9.3 验收目标

| 指标 | 目标与口径 |
| --- | --- |
| 证据 Recall@8 | 新链路较 A 提高至少 5 个百分点；按 gold 范围覆盖统计，分题型报告 |
| 精确术语/编号题 | 必要证据召回率不低于 90%；同时报告相对 A 差异 |
| 最终回答 | 人工复核事实错误率、任务完成率、误拒答率；不能以拒答增多换取表面低错误率 |
| 质量回退门槛 | 任务完成率下降超过 2 个百分点、误拒答率或无依据回答率上升超过 2 个百分点，不发布该配置；小样本无足够证据时扩大评测，不宣布统计非劣 |
| 引用与权限 | 测试集未知/越权/已撤销引用为 0；摘录校验通过率 100%，失败输出单列 |
| 延迟 | 同硬件、并发和缓存条件下报告端到端 P50/P95；P95 较 A 增长不超过 20% |
| 成本 | 所有尝试的平均模型 token 与可用费用较 A 增长不超过 20%；缺费用收据不能认定满足费用门槛 |
| 故障行为 | 分支故障、重排非法输出、超时、取消、索引不一致都有明确状态，不输出伪造依据 |

以上是发布门槛。报告必须同时列样本数、失败数、绝对值与差值；通过离线门槛也不能表述为真实商家转化率改善。

## 10. 实施顺序与回滚

1. **P0：冻结基线。** 保存语料、配置、模型版本和实际入口结果；建立评测集与阶段日志。
2. **P1：补数据基础。** 版本化来源、稳定 ID、新分块、双索引发布清单；验证删除与权限复核。
3. **P2：接混合召回。** 先影子运行 C0/C1，再接入多查询；保留分支失败信息。
4. **P3：补上下文与重排对照。** 分别验收父段补全、重排输出校验及专用模型取舍。
5. **P4：引用与入口验收。** 覆盖检索 API、同步回答、托管助手；验证正文、来源、业务工具引用一致。
6. **P5：灰度。** 按服务端稳定请求分组逐步启用，记录配置版本；发生越权/撤销来源泄漏立即关闭新链路，其他质量、延迟或成本越线退回上一通过版本。

回滚切换活动配置和索引清单，不删除新旧原文；权限拒绝集合继续生效。在途请求保持自己的 generation，但输出前仍复核删除和授权。新增评测结果写新报告，不覆盖历史实验成绩。

## 11. 必需验证与交付物

- 单元/合约验证：长句切分、重叠边界、ID 稳定性、重复导入、版本更新、索引一致性、融合确定性、重排非法输出、引用与摘录校验。
- 集成验证：真实入口走到共享服务；多分支故障降级；资料不足与服务故障区分；取消释放资源；回滚后无新版本缓存污染。
- 权限验证：不同授权范围不可共享候选/缓存；父段补读、删除、撤权、旧 generation 和在途输出均不能绕过复核。
- 评测交付：冻结语料清单、题集与标签、组别配置、原始调用收据、全部失败、分题型报告、配对差异、耗时与费用报告。
- 文档交付：实现与迁移说明、开关默认值、灰度记录和回滚操作；只有完成对应验收后，才更新对应阶段状态，不把本地功能测试当作正式效果验收。
