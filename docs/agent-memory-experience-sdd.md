# MiniAdsWall 记忆接入与运营经验复用 SDD

- 日期：2026-10-20
- 状态：本地功能与自动验证已完成，限定主体启用；生产建议质量验收未通过。实现范围、设计差异与失败样例见 [验收记录](validation/agent-memory-experience/implementation-2026-10-20.md)。下文仍是原目标设计，不把验收目标冒充已有成绩。
- 范围：托管与同步入口共享记忆策略、摘要限长、偏好版本、运营案例读取、对照评测。
- 依赖：[运营反馈 SDD](agent-feedback-sdd.md)、[实施计划](agent-memory-experience-coding-plan.md)。运营案例的采纳、改稿、执行回执和效果观察继续由反馈 SDD 负责。

## 1. 要解决的问题

目标：商家换一次会话，助手仍能使用有效偏好；遇到相似运营问题，能引用已核查的处理案例；历史增长后，上下文成本仍有上限。

示例：商家曾明确要求“优先获取咨询”。再次询问投放建议时，助手可使用该偏好，但本轮明确改为“优先成交”时立即覆盖本轮判断。历史同类案例只能提供测试思路，当前预算、出价和效果必须来自本轮可信业务数据。

本次不训练 MemT、不改模型权重、不把数字记忆矩阵接入 API 模型。借鉴的是经验筛选、按需读取、成本约束和验证方法，不声称实现模型原生记忆或自主持续学习。

## 3. 不变的边界

1. MySQL 保存消息、记忆版本、撤回状态和任务；Redis 是缓存，Chroma 是派生索引。索引丢失可从真值重建。
2. 原始报表、执行回执和素材版本仍属于业务系统。记忆只保存引用，不复制为新的“当前事实”。
3. 用户明确的本轮指令优先于旧偏好；业务授权、数据权限和硬规则始终由程序检查，记忆不能覆盖。
4. 历史回答、聊天摘要、用户认可都不能单独证明建议有效；不从聊天自动提炼“成功投放规律”。
5. 不新增真实调价、预算扣费、删除或发布能力。记忆读写不构成业务操作授权。
6. 跨主体默认隔离；经验即使相似，也不能越权读取其他商家的内容。

## 4. 目标结构与归属

```text
Koa 认证主体 → 托管身份/会话 → preflight
                                  ↓ execute 分支
                         MemoryContextService
                  ┌──────────┼─────────────┐
                会话摘要    有效用户偏好    运营案例提供器
                  └──────────┼─────────────┘
                    条件检查、去重、裁剪、来源清单
                                  ↓
               本轮业务快照 + 已检查知识 + 记忆 → 生成
                                  ↓
              Repository.finish 事务：消息/终态/记忆任务
                                  ↓
                  后台任务生成摘要、偏好候选、索引
```

- 新增 `memory/context_service.py`：统一装配、预算、来源标记；不处理真实业务写入。
- 新增 `memory/repository.py`：类型化读写、版本 CAS、撤回；使用既有托管数据库迁移体系。
- 新增 `memory/jobs.py`：消费独立记忆任务，复用进程生命周期管理，不混用现有 run 调度 outbox 的语义。
- 新增 `memory/experience_provider.py`：定义运营案例读取接口。真值、案例版本、确认与撤回属于反馈模块。
- 同步和托管复用服务与类型，不直接把 Redis 版 MemoryManager 整个塞入 Pipeline，也不把同步消息复制成第二份托管历史。

## 5. 类型与数据契约

### 5.1 统一读取契约

拟新增内部调用：

```python
build_context(scope, query, history_watermark, budget) -> MemoryBundle
```

`scope` 包含服务端解析的 auth_subject、hosting_user_id、workspace_id、session_id、可选 brand_id 与授权版本。同步没有可信身份映射时只使用会话内记忆，不开放跨会话/跨用户检索。浏览器不得直接提交 scope 或记忆正文。

MemoryBundle 包含：schema_version、snapshot_id、history_watermark、summary、preferences、episodes、experiences、sources、estimated_tokens、status、reason_codes、各存储延迟。status 为 complete/partial/unavailable/disabled；空结果是正常 miss，不等于服务故障。

每条记忆至少返回 id、kind、version、source_ref、updated_at、有效状态。模型生成的推测与明确用户偏好必须区分，不输出无依据的置信度百分数。

### 5.2 存储提案

复用既有 `memories` 保存摘要/情景记忆，增加必要的作用域、状态、哈希、来源范围和更新时间字段；保留原 last_reply 的旧读写兼容。新增字段先 nullable，分批回填，最后再决定约束。

| 对象 | 必要字段/约束 |
| --- | --- |
| 摘要/情景记录 | user/workspace/session、kind、version、status、summary、content_ref、source_start_seq、source_end_seq、content_hash、expires_at；同一范围/类型/内容哈希唯一 |
| `memory_preferences` | subject/workspace、field、value_json、version、status、source_message_ref、source_seq、confirmed_at、updated_at、expires_at；每个主体/工作区/字段只有一条当前版本 |
| `memory_preference_events` | 偏好版本历史，记录创建、更正、撤回、来源；不通过 delete 再 add 实现更新 |
| `memory_jobs` | scope、source_run_id/source_turn_id、job_kind、source_watermark、payload_ref、状态、attempts、next_attempt_at、lease_until、lease_token、error_code；来源+任务类型唯一 |
| `memory_tombstones` | scope、memory_id/field、撤回版本、撤回时间；先写真值，再异步删除缓存和索引 |

记忆任务状态为 pending/running/retry/succeeded/dead；数据库租约领取，完成写入校验 lease_token，过期领取者不能提交。退避重试上限 5 次，进入 dead 后可审计重放，同一来源不能重复生效。

大文本走既有对象存储 content_ref，引用包含内容哈希；对象先写后提交引用，提交失败的孤立对象由清理任务回收。索引记录带真值 id/version，检索后回查真值与权限，不信任索引元数据中的有效状态。

### 5.3 偏好更新

沿用现有 PROFILE_FIELDS 白名单与清洗规则。模型仅提取候选及原文依据；候选不支持回指原文时拒绝。明确更正按服务端有序消息水位覆盖旧版本；并发使用 CAS，旧任务不得覆盖新版本。不同会话先按服务端提交顺序处理；语义冲突但没有明确更正关系时标记 pending_confirmation，不静默覆盖。

临时 ad_id、预算、出价、即时点击、授权口令不进入长期偏好。用户本轮明确说“只这一次”时不得长期保存。暂不能可靠区分长期偏好与临时要求时只留本轮上下文。

## 6. 两条入口的读写流程

### 6.1 托管入口

1. 认证与会话归属检查沿用现有链路。preflight 使用本轮消息与必要近期对话，记忆不补全动作参数、不改变确认结论。
2. execute 分支获取已提交历史水位；按该水位读取摘要、偏好和历史片段。读取完整 content_ref，预览仅供列表显示；对象缺失标记 partial，不把截断文本当完整证据。
3. 运营案例按可信业务范围查询；先授权过滤、条件过滤，再语义排序，最多返回 3 条。没有反馈模块时返回 disabled，不用普通聊天冒充案例。
4. 用统一预算装配。摘要覆盖的旧消息不再逐条重复注入；历史回答明确标记“非事实证据”。
5. 现有 RAG 证据检查继续保留。案例可以补充做法依据，不能替代本轮账本或补齐缺失指标；未通过检查的案例不能支撑确定性建议。首版证据门不支持案例时，仅注入经条件核查的参考流程，并限制为待验证思路。
6. 生成前把选中的记忆版本、来源和预算持久化为上下文快照引用，写入 checkpoint 时合并现有 tools/workspace_version，不覆盖已有检查点内容。
7. `Repository._finish` 在成功终态事务中追加记忆任务；与原消息/终态原子提交。Pipeline 返回前不写长期记忆。取消、失败、超时、旧 fence、不完整流式输出均不产生自动学习任务。
8. succeeded 不等于建议正确：先只生成会话摘要与偏好候选。confirm/clarify/refuse 等控制回答即使正常成功也不抽取运营经验；任务元数据记录实际 decision 和可学习类型。

### 6.2 同步入口

复用 context_service；保留原响应协议。进入长期记忆模式前，使用经过认证的主体和服务端 turn_id，在统一数据库提交同步问答与任务，唯一键防重；不能继续仅依赖 `asyncio.create_task` 保证写入。

兼容期没有可信主体映射的请求，只允许隔离的会话记忆。通过协议版本和功能开关切换；不以“接口仍收 user_id”作为身份认证。长期启用前必须验证客户端传入其他 user_id 无法读取对应记忆。

### 6.3 恢复与撤回

同一次 run 的工具/模型恢复默认复用上下文快照，不在重试中随机换案例；新的 resumed run 可构建新快照并记录差异。复用前重新检查权限、撤回和案例版本有效性；失效则移除相关项并生成新快照，权限优先于重放一致性。

读取超时或缓存不可用时降级到近期对话与本轮业务数据；不把故障解释为“用户无偏好”。用户明确询问过去事实且记忆不可用时，明确说明暂未查到，不能猜。

## 7. 摘要限长与检索预算

以下为首版默认上限，需通过评测调整：

| 项目 | 上限 |
| --- | --- |
| 会话摘要 | 800 tokens，同时不超过 2,400 汉字/字符 |
| 结构化偏好 | 400 tokens |
| 情景片段 | 最多 3 条，共 800 tokens |
| 运营案例 | 最多 3 条，共 1,200 tokens |
| 记忆总预算 | 3,200 tokens；不含近期对话、系统提示和本轮业务快照 |
| 全输入预算 | 根据服务端模型上下文窗口减去输出预留与安全余量；超限不得直接发给模型 |

使用实际模型 tokenizer；不支持时采用保守估算并标注 estimated。先保留本轮指令与关键业务限制，再保留近期对话和有效偏好；历史片段和案例按相关性裁剪。业务数据过大时走独立结构化精简策略，不能删除影响判断的缺失标志和统计范围。

压缩改为“旧摘要 + 新增消息 → 新摘要”，并记录已覆盖水位；输出经程序长度校验，最多一次修复，仍超限则使用有界旧摘要并保持旧水位，待后续重试。不得把未摘要的消息标为已覆盖。原文保留到真值存储，不能因为摘要成功就删除唯一原文。

异步摘要尚未追上历史时，在总预算内读取最近完整轮次，不制造已覆盖假象。摘要缓存 key 包含作用域、summary_version 和水位；偏好/案例撤回先在真值层阻断，不能等待 TTL 才生效。

## 8. 运营经验准入与来源

运营案例提供器适配反馈 SDD 的真值和索引；不新建第二套运营案例库。

案例最少包含：case_id/version、brand/owner scope、适用目标、渠道、素材/活动版本、触发条件、建议与人工修改理由、report_ref/hash、执行状态、执行回执引用、后续观察引用、限制、审核/撤回状态。

区分三个层级：

- reviewed_procedure：人工确认流程或处理方法；只能支持做法建议。
- executed_case：有可信业务执行回执；只能证明动作发生。
- observed_case：有同口径前后快照且通过数据完整性检查；支持描述观察结果，仍不证明因果。

通用流程型案例可不含效果指标；涉及“降低成本/增加订单”的效果型案例必须给出指标定义、窗口、样本、费用覆盖与素材版本条件。条件不齐时排除效果结论，不能把缺失值变零。过期、撤回、权限失效、素材变化导致不适用的案例不注入。

候选按目标/渠道/场景过滤，语义排序后检查适用条件。相似度只表示相关性。没有可用案例是正常结果，按现有知识与本轮事实回答。来源在内部 trace 保留完整 id/version，商家端只显示来源标题、日期和可授权查看的记录链接，不展示内部字段。

## 9. 配置、管理与可观察性

拟新增：`AGENT_MEMORY_READ_ENABLED=false`、`AGENT_MEMORY_WRITE_ENABLED=false`、`AGENT_EXPERIENCE_READ_ENABLED=false`、`AGENT_MEMORY_TOKEN_BUDGET=3200`、`AGENT_MEMORY_READ_TIMEOUT_MS=800`。案例提供器与其他读取共享总截止时间，不能各自叠加 800ms。关闭读取不等于撤回数据，关闭写入后消费者也不得继续处理新增候选。

内部管理契约包括列出偏好及来源、明确更正、撤回、清除会话摘要/情景片段；仅经认证的主体操作自己的范围，带 expected_version 防止覆盖。运营案例撤回仍走反馈模块。外部路由在实施时扩展显式白名单，不开放任意代理。

trace 记录：run/turn、scope 哈希、history_watermark、memory_snapshot_ref、命中数、选中版本、裁剪数、token 估算/实测、各读取延迟、降级原因、任务来源。监控记录任务积压、重试/dead、摘要落后水位、缓存命中、撤回拦截；日志不打印整段商家聊天和敏感信息。

源消息删除后，清除由其派生的摘要/情景/偏好与索引；混合来源摘要必须重建，重建前停用。按授权与数据保留策略清理原文；审计仅保留不含正文的操作记录，不能通过旧快照重新读到已删除内容。

## 10. 对照评测与上线门槛

冻结数据集、标注、模型版本、提示词、检索配置和随机种子。三组必须使用同一批本轮业务快照：A 无长期记忆；B 当前聊天记忆基线；C 本设计记忆与已审核案例。额外消融 C-无案例，分离记忆接入和案例复用的收益。

首版至少 100 个问题，覆盖跨会话偏好、更正/撤回、长历史、相似场景不适用、指标缺失、过期案例、注入文本、跨主体访问。历史案例按时间切分；同一事件/商家处理链不得跨训练候选库与测试集泄漏。使用脱敏或人工构造数据，明确标注来源。

| 指标 | 计算方式 | 首版目标（不是已有成绩） |
| --- | --- | --- |
| 偏好正确使用率 | 该使用且正确使用/应使用问题数 | ≥95% |
| 更正和撤回遵循率 | 不再使用旧值/相关测试数 | 100% |
| 越权和记忆授权绕过 | 程序检查+攻击样例 | 0 次 |
| 案例引用准确率 | 来源存在、授权、版本有效且支持表述/引用数 | 100% |
| 无依据建议比例 | 未被业务/知识/案例支持的可核查主张/全部可核查主张 | 不高于 B |
| 建议正确率 | 双人独立按冻结规则标注，分歧复核 | 不低于 B；报告差值与置信区间 |
| 人工修改量 | 必须修改的动作项/全部动作项 | 报告 C 相对 B 的变化，不先承诺提效 |
| 记忆读取 P95 | 从装配开始到完成/降级 | ≤800ms |
| 成本 | 输入/输出 token + 摘要/提取/索引费用，按活跃会话摊销 | 长历史总成本不高于 B；短历史单独报告 |

另外报告端到端 P50/P95、冷/热缓存、记忆写入延迟和依赖失败时表现。不把召回率当建议正确率，不直接宣称提升商家收入。100 题只作为首版准入，不证明生产收益或大规模可靠性。

必须故障验证：重复 finish、旧 fence、取消后的迟到结果、消费者重复执行、摘要并发覆盖、Chroma/Redis 中断、对象缺失、读取超时、快照恢复后撤回、跨主体索引候选、超长摘要与提示注入。

## 11. 实施阶段与回滚

1. M1：统一类型/预算与摘要修复，保持功能默认关闭；以固定输入证明摘要有界且原文可追溯。
2. M2：托管接入、终态事务任务与版本化偏好；同步仅在身份映射/持久写入就绪后接入。
3. M3：先影子读取，记录命中但不影响答案；通过隔离、撤回与恢复检查后按主体灰度。
4. M4：反馈案例真值和审核流程可用后，接入经验提供器；此前明确报告该阶段未交付。
5. M5：冻结集评测与故障验证通过，再扩大读取范围；写入开关单独灰度。

回滚先停写入和任务消费，再停读取与案例注入，恢复现有历史+业务快照路径。新增表/字段保留，禁止通过降级迁移删数据；无效索引可清除重建。业务快照、权限和 RAG 证据门不随本功能回滚。

## 12. 交付物与验收结论格式

交付代码、增量迁移、接口契约、回滚开关说明、固定评测集及 `docs/validation/agent-memory-experience/` 报告。每个阶段分别写“已实现/未实现/本地验证/未运行验证”，不以文档完成代替功能完成。

方案来源：[MemT-1.0 原文](https://arxiv.org/html/2610.26825v1)，重点参考第 6 节效率与记忆保真度、第 7 节检索经验复用与局限。本项目方案为工程改造建议，论文的 1.86 倍速度和 66 倍 KV 存储差异不作为本项目收益或验收指标。


## 13. 实施收敛说明（2026-10-20）

- CP07 采用“同步门面→同一托管 run”，服务认证、主体级旧会话别名与幂等避免第二套执行状态。等待超时返回 202，调用方保留 run_id、原 payload 与 key。
- CP09 先交付由 marketing/feedback 拥有的人工审核通用流程库，授权粒度为托管主体/工作区；禁止承载品牌效果结论。完整品牌反馈与效果观察仍遵守原反馈 SDD，不另造虚构执行证据。
- 情景检索首版为 SQL 上最近 50 条摘要的确定性词项检索，未复制旧 Chroma 集合，未宣称实现语义向量重排。
- 删除采用软删除、派生停用和读取阻断；保留审计与存储保留策略，物理共享对象回收不通过 HTTP 删除任意对象完成。
- 偏好精确查询、明确记忆声明、显式操作经验查询由程序处理，不借它们绕过任何广告执行授权。普通建议继续受原知识证据门限制。
- 自动评测与单人脚本核查不能代替“双人建议质量标注”。新版结构化对照为 99/100，原文字记忆为 100/100；生产质量和收益验收不标完成。
