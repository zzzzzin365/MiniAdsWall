# 广告运营助手：当前数据与营销知识

目标：助手根据所选周期的数据给出最多三个投放优化动作，展示数据口径、广告名称、知识依据和验证指标。

按用户指定的应用口径，已有账本记录的广告按已投放广告处理，指标作为广告实际数据进入分析；应用界面、模型业务输入和回答不显示模拟标签。原始固定账本与离线实验记录保持可追溯。

实现链路：AIAssistantPanel 传消息和 3/7 天窗口 → Koa 验证运营身份 → MySQL 读取最多 50 条广告 → 服务端从与看板相同的固定账本计算窗口指标 → 持久化 hosted run → 广告数据工具 → 共享 `knowledge_base_cosine_v1` 查询改写、最多四路并行召回、去重与重排 Top-8 → 证据检查 → AdsAgent 流式建议 → 附知识标题、片段 ID、原始链接，并持久化来源 trace。

数据口径：广告配置及累计点击来自 MySQL；看板曝光、费用、支付订单和退款来自同一份固定账本。已有历史曝光的广告为已投放，暂停状态单列；不存在账本记录的广告按未投放处理，不编造效果。所选窗口曝光为零不代表从未投放。费用单位为分；订单转化率分母为点击；净收入扣退款但不扣商品成本，ROAS 不是利润。历史素材和当前素材不一致时，历史效果不能归给新素材。样本不能冒充账户全量。

知识检索默认开启，`HOSTING_RAG_ENABLED=false` 可回滚。`HOSTING_RAG_EVIDENCE_TIMEOUT_SECONDS=16` 限制证据检查时间；检索最多 15.5 秒。不通过证据检查或没有可用营销片段时明确说明，不编造建议。只在明确要求模拟时调用出价模拟，不修改广告。

验证：服务端窗口账本汇总与看板一致；伪造广告/指标被服务端覆盖；无数据和零分母边界；完整快照进入证据检查及生成；被拒绝片段不进入模型或来源列表；真实本地网关到 Worker 的模型调用记录保存于 `docs/validation/assistant-marketing-rag-live.json`。

本地验证结果：20 条已有投放记录的广告，7 天曝光 49,990、点击 1,043、花费 587.82 元、支付订单 18、净收入 1,143 元。保留 4 条通过检查的营销知识，实际模型完整返回三个优化动作和知识片段 ID；单次运行 32.6 秒，不作为性能基准。浏览器已验证列表及详情的投放状态、无模拟标签、助手会话回看时完整建议和来源可见。前后端构建通过，相关网关、账本及 Python 检查通过。

首次运行触发模型输出截断，已保留失败记录 `assistant-marketing-rag-attempt1.json`；修复输出上限与回答长度后，新请求完成。没有把失败运行计为成功，也没有执行广告变更。
