# 知识库真实向量检索实验（2026-10-12）

复现：`.venv/bin/python -m evaluation.run_vector_retrieval`

使用临时隔离 ChromaDB，复用项目 KnowledgeBase 的默认文档、切片、入库和 search 方法。不修改正在使用的知识库，不调用回答模型、查询改写或重排。ChromaDB 0.5.23，默认 ONNX all-MiniLM-L6-v2；30 篇内置资料实际生成 30 个片段。

68 个作者自编且预先标注的问题：30 个直接问法、30 个口语改写、8 个双资料问题。完整题目、指定关键片段 ID、实际返回内容和分数保存在 `docs/evidence/vector-retrieval-cases-v1.json` 和 `docs/evidence/vector-retrieval-results-v1.json`。

| 取前 K 个 | 平均关键片段召回率 | 至少命中一个关键片段 | 所有指定依据找齐 |
| --- | ---: | ---: | ---: |
| 1 | 13.97% | 16.18% | 11.76% |
| 3 | 25.00% | 27.94% | 22.06% |
| 5 | 35.29% | 39.71% | 30.88% |
| 10 | 61.03% | 64.71% | 57.35% |

召回率：每题“找到的指定关键片段数 / 该题指定关键片段数”，再对题目取平均。命中率：至少找到一个指定关键片段的问题比例。找齐率：所有指定关键片段都找到的问题比例。它们都不是最终回答正确率。只指定必要目标片段，没有穷尽标注所有可能相关资料，所以报告中的 precision 仅针对指定目标，不宜解读为完整的相关性精确率。

Top 3：直接问法命中 10/30；口语改写命中 5/30；跨资料问题至少命中一个为 4/8，但找齐为 0/8。Top 10 跨资料找齐仅 1/8。

失败例：“CTR怎么算？”返回广告运营风险边界、素材与 A/B 测试、数据看板解读，未找到指定 CTR 文档。“CPM费用怎么算？”返回 CPA/CPS、CPV、CPC，未找到指定 CPM 文档。

代码配置没有设置 `hnsw:space`，本地安装版本默认是 L2 距离；源码注释的余弦相似度不符实际配置。`1-distance` 不是正确概率，不应称为百分比准确率。

结论：在这组中文问题和内置小知识库上，当前默认向量检索漏检明显，不能声称能稳定覆盖关键依据。增加 K 有改善，但不保证跨资料完整性。值得下一步对照验证中文/多语言 Embedding、关键词与向量混合召回；当前实验未测试这些改动。
