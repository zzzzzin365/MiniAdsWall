# 外部营销知识与 3600 万向量压测

## 真实资料

2026-10-14 使用 agent-reach / OpenCLI 的已有浏览器会话搜索知乎、小红书和 X。
知乎两篇使用 Jina Reader 读取，另一篇使用浏览器 DOM 读取公开预览。
归档首批 7 篇文章/笔记的原创摘要，下载并逐张检查 6 张图片，图片另有可见内容描述。
未执行点赞、评论、关注、私信，也未自动登录或读取浏览器 Cookie。

| 平台 | 数量 | 内容 |
|---|---:|---|
| 知乎 | 3 | 创意与投放案例；广告形式与展示图；广告创意组件（仅预览） |
| 小红书 | 2 | 多邻国品牌IP案例；广告主投放准备与计划搭建 |
| X | 2 | 营销知识资料组织；创意方案六项评估维度 |

原文地址、作者、阅读范围、摘要、图片来源、文件 SHA-256 在
`external-marketing-2026-10-14.json`。本机副本为 `data/external-marketing/catalog.json`，
原始图片在 `data/external-marketing/images/`。全文与未读的付费/私有内容没有冒充摘要来源。
外部案例不是商品事实、当前平台政策、效果证明或素材使用授权。

实际写入 `knowledge_base_cosine_v1`：7 个摘要向量 + 6 个图片描述向量 = 13。
导入后总数为 43。二次导入新增 0 个，仍为 43。
工作台 `/studio/generate` 检索当前目录的资料，模型只能引用本轮召回的 `reference_ids`；
结果显示原文链接、作者、预览边界、引用状态与本机原图。个人品牌素材仍走独立的授权检索。
不调用生成模型的检索入口：`GET /api/merchant/v1/studio/reference-search?q=...`，需要运营凭据。

导入命令：

```bash
.venv/bin/python scripts/import_external_marketing.py
```

未同步收藏或抓取全部站点。后续资料应有可核验来源和摘要，再进入同一导入流程。

## 验证结果

流程：工作台查询 → Koa → 内部认证的 Python → 真实 Chroma → 来源与本机图片 → 页面。

| 边界 | 结果 | 证据 |
|---|---|---|
| 摘要与图片入库 | 通过 | `external-marketing-import.json`：30 → 43；重复导入新增 0 |
| 运行中 API 到知识库 | 通过 | `docs/validation/external-marketing/runtime.json`：Semrush 查询返回实际图片描述 |
| 来源图片读取 | 通过 | HTTP 返回图片字节 SHA-256 与归档一致；未认证请求返回 401 |
| 返回值到页面 | 通过（界面测试数据） | `browser.json` 与 `references.png`：来源、作者、本机图片、320px 宽度 |
| 引用 ID 校验 | 通过（模型响应模拟） | Python 专项拒绝伪造引用 ID，保留预览阅读边界 |
| 在线生成模型 | 未验证 | 本轮未提交付费生成请求 |

15 个 Python 专项、2 个真实 MySQL 生命周期测试及前后端构建通过。
浏览器测试使用本次真实归档图片与模拟会话，没有修改真实业务记录。

## 独立合成向量压测

用户明确选择“3600 万合成向量，仅用于容量压测”。已实际生成并保留数据：

- 数量：36,000,000；维度：384；格式：归一化 float32。
- 分片：36 个，每片 1,000,000 条；每片记录写入时 SHA-256。
- 实际数据字节与磁盘分配字节均为 55,296,000,000（55.296 GB，约 51.50 GiB）。
- 写入用时：140.422 秒（含 fsync）。
- 4 个查询合批全量扫描：110.345 秒；实际扫描 36,000,000 条。
- 查询分别取第 0、12,000,000、18,000,000、35,999,999 条，均找回自身作为 top-1。
- 进程峰值 RSS：1,791,868,928 字节，约 1.67 GiB。

后端为分片磁盘文件 + 精确全量扫描，不是 Chroma/HNSW 的 3600 万索引容量证明，
也不是高并发、P95 延迟或真实 RAG 质量评测。合批扫描耗时不能当成单查询延迟。
数据在 `data/benchmarks/synthetic-36m-384-f32/`，没有写入业务知识库。
报告与分片清单复制到 `docs/validation/vector-capacity-36m/`。

```bash
VECLIB_MAXIMUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  .venv/bin/python scripts/benchmark_vector_capacity.py
```

脚本按真实文件尺寸校验向量数量，支持已完成分片的断点续写；预留 20 GiB 磁盘。
保留数据会持续占用约 55.3 GB，移除整个合成压测目录可释放空间，不影响真实知识库。
