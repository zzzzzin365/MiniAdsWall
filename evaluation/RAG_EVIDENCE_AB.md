# 回答前证据检查：固定输入对照实验

本实验验证“增加证据检查是否减少无依据的回答”，不引入 Jev。`pilot-v1` 保留首次实验；当前应用接入了 `core/rag_evidence.py`，新评测默认使用 `runtime-v2`。应用接线说明见 `docs/rag-evidence-integration.md`。

## 比较方法

- 两组使用同一模型、同一 `AdsAgent`、同一业务 Skill、同一问题和业务数据。
- 基线按接入前的聊天逻辑注入三个知识片段，保留原有“知识不足时结合通用知识”的提示。
- 实验组先逐段检查支持程度，代码按固定阈值 `0.7` 过滤；再单独检查实际保留的资料和业务数据是否足够。
- `pilot-v1` 充分时使用同一生成方法和提示；`runtime-v2` 使用应用当前的证据检查及受限事实提示。不足时跳过生成，返回具体缺失信息；因此 v2 比较整体接入策略，不能把变化只归因于过滤。
- 两组交替先后执行。评分时随机交换匿名答案位置，避免评审看到组别。

`rag_evidence_cases.json` 在首次模型评测前生成并固定，共 20 个合成案例：

| 类型 | 数量 | 可以完整回答 |
| --- | ---: | --- |
| 知识规则充分 | 4 | 是 |
| 规则和业务数据充分 | 4 | 是 |
| 缺少业务指标 | 4 | 否 |
| 资料只有相关话题 | 4 | 否 |
| 广告范围、窗口冲突、规则冲突、零分母 | 4 | 否 |

参考标签与答案仅送给评审，不送给证据检查或答案生成。固定集不参与调阈值。
这是开发者定义参考标准的合成试验集，没有独立人工标注；保留片段判断输出是模型估计，并非经过校准的概率。

## 统计口径

- **事实错误率**：无依据的具体业务结论、错误数值、混用统计范围或窗口。一般建议、正确公式、明确标为假设的例子不自动算错误。
- **误拒答率**：8 个可回答案例中，系统却称无法回答或要求补充已有信息的比例。
- **正确率**：能答时给出核心答案；不能答时准确说明缺失或冲突，且不编造问题所问事实。
- **可用性**：单独计入模型失败、JSON 校验失败和评审失败。失败不算正确拒答，也不填入零错误。
- **延迟**：提供调用耗时之和与包含实验限速等待的总耗时；前者适合比较额外调用负担，二者都不是生产压测数据。
- **消耗**：两组用户请求流程、评审调用分开统计模型调用数、输入/输出 Token 与服务商实际返回的美元成本。缺失成本保持 `null`，不能当零。
- **成对比较**：在两组和评审都完成的同一案例上计数，并记录精确 McNemar 双侧检验。小样本及同模型评审不能证明真实流量收益。

## 运行

```bash
# 如需新建数据版本：修改构建器并生成新的文件；不能覆盖历史冻结集。
.venv/bin/python -m evaluation.build_rag_evidence_cases

# 使用当前配置模型。默认只允许免费 OpenRouter 模型。
.venv/bin/python -m evaluation.run_rag_evidence_ab \
  --gate-version runtime-v2 \
  --output docs/evidence/rag-evidence-ab-new-run.json

# 首次预检中原配置 nex-agi/nex-n2.5-mini:free 返回 HTTP 404，
# 因此本次仅在实验进程使用已成功预检的免费模型，不改 .env。
.venv/bin/python -m evaluation.run_rag_evidence_ab \
  --gate-version pilot-v1 \
  --model nvidia/nemotron-3.5-lightning:free \
  --output docs/evidence/rag-evidence-ab-pilot-v1.json

.venv/bin/python -m unittest discover -s tests -p 'test_rag_evidence_gate.py' -v
```

结果逐案例保存，原报告不覆盖。报告记录模型、阈值、随机种子、数据/源码/Skill 哈希，保留两组答案和评审理由，供复查。

## 结论边界

候选片段采用冻结快照，因此只验证回答阶段；没有运行 ChromaDB 召回、HTTP 路由、意图识别、业务工具或记忆链路。
相同模型负责生成与匿名评审，有共同偏差，不能把自动评分当成人工真值。
本次没有修改阈值来适配案例，也没有宣称已经提升线上质量、校准概率或接入 Jev。
v2 的证据检查受 8 秒截止时间约束，实验限速等待也会消耗该时间。应分别查看流程失败率和回答质量，不能将失败算为成功拒答。旧报告存在同模型评审误判，7 对完整样本的源码与参考答案复查以 `docs/evidence/rag-evidence-ab-pilot-v1-review.json` 为准，不能宣称已证明线上改善。
若误拒答或额外延迟明显增加，可关闭 `RAG_EVIDENCE_ENABLED`，扩大评测后再调整阈值。
